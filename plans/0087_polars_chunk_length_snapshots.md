# rnx 0087: chunk-length snapshots

Status: plan. Record 0086 closed at plan `f60634b` and implementation `00b2ece` on `origin/main`. This record takes one return shape from the remaining foreign-type pool: `ChunkedArray::chunk_lengths`. Rune receives an owned vector of integer chunk lengths; neither the iterator nor any Arrow array crosses the binding boundary.

## Measured target and contract

The 0086 surface has 2,107 script-available operations, 1,334 value-tested, 1,936 unsupported, and 212 refused proven receiver pairs. `ChunkedArray::chunk_lengths` (`polars_core:3680`) is refused on all 16 proven aliases because its return resolves to `Map<Iter<Box<dyn Array>>, fn(&ArrayRef) -> usize>`, classified as a foreign type. No alias has a binding. Thus **one operation and 16 bindings** are the ceiling for 0087; if all emit, the refused proven-pair pool falls to 196 before any unrelated disposition changes.

Pinned Polars 0.55.2 defines `ChunkLenIter<'a>` as that `Map` type in `polars-core/src/chunked_array/mod.rs:61`, and `chunk_lengths` as `self.chunks.iter().map(|chunk| chunk.len())` at `:472-475`. The iterator borrows the receiver, yields one `usize` per chunk in order, and has an exact size. An empty array can still have an empty *chunk* in Polars, so copy the iterator's actual results rather than assuming its output is empty or deriving it from total length. `chunks()` (`polars_core:3681`) returns Arrow array references and remains refused; this record does not map arrays to integers under another method name.

## Ownership and bound

Admit the `ChunkLenIter` return only on the exact canonical `chunk_lengths` path through a release-file gate. Drive the iterator to completion while the receiver borrow is valid, including inside the engine closure if that binding is routed. Copy each length to a Rune integer using a checked `usize` → `i64` conversion; an unrepresentable value returns a typed conversion error rather than wrapping. The returned `Vec<i64>` is independent of the receiver. No generic `Map`, `Iter<Box<dyn Array>>`, Arrow `ArrayRef`, or other foreign iterator is thereby admitted.

Use the existing `materialize_limit()` on the number of chunks. Because `ChunkLenIter` is exact-size, reject an over-bound result from its length before allocating or consuming any item. At the exact bound, return all items in original order. The error names `chunk_lengths`, the requested item count and the bound. Error or unwind leaves the receiver usable and the materialization guard restored. The method is read-only and does not alter chunk layout or null state.
