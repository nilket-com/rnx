# rnx 0112: generic Rust trait impls on proven script values

Status: plan. Record 0111 is closed on `origin/main` at `ea5ade1`. The target is the pinned Polars v2 Rust API (`da47b7405f0e2d188e71cce7c2d588c695f4098d`); 0.55.2 remains an active compatibility build. This record audits and applies shared rules to the **732** v2 foreign-trait impls in the 0111 `generic_impls` batch. It is one batch record with two admission paths, not a record per trait or type.

The starting v2 scoreboard is 3,454 available and 2,244 value-tested of 6,441 applicable callables. The pool comprises 194 `Serialize`, 193 `Deserialize`, and 345 other impls. The latter include `FromIterator` 49, `From` 42, arithmetic and bitwise operators about 130, `Clone` 16, `Deref` 13, `AsRef` 11, `IntoIterator` 11, `Iterator` 10, `Index` 8, `Debug` 7, `Extend` 5, and a tail. These are upper bounds, not promised bindings. No denominator change is authorized merely because a trait needs a generic type argument.

## Admission before generation

Build a table of all 732 inventory keys first. For each row record the canonical trait path **and its trait arguments**, `owner`, `impl_for`, impl bounds and where predicates, associated types, receiver and method signature, candidate script wrapper or input type, the proof result, and final disposition. The current inventory stores arguments such as `From<A>` in `name` while `canonical_path` names the bare trait; validate their combined identity or extend extraction rather than dropping the arguments. Distinguish a retained impl on the wrapped target from an outward `From<Owner> for Other` listing; a row in a type's rustdoc page does not by itself prove the wrapper owns the impl. Do not infer an impl from a trait's short name or a shared base name.

For an impl head such as `ChunkedArray<T>` or `&ChunkedArray<T>`, unify the recorded `impl_for` with each wrapper's exact canonical identity, including reference ownership, then discharge **every** impl bound and where predicate using the existing `applicability` proof. Foreign trait impl rows currently have `impl_head = None`; supply a validated synthetic head from `impl_for` to that proof, never treat `owner` as the head. A bare generic parameter, unresolved projection, ambiguous alias, unsupported lifetime or associated type, or unproved external bound remains a named refusal. Resolve `Self` and associated `Output`/`Target` only from the same impl record after substitution. Deduplicate aliases with the same underlying identity, and use the existing Rune slot/name collision checks. Validate each trait family's full canonical path, type arguments, receiver, parameters, return and associated values **before any binding text or registration**. Include negative inventory controls that change one field at a time and require no emitted text. Keep per-pair refusal reasons in the surface; count the callable once and bindings separately.

## Serde instantiation: a JSON script boundary

`Serialize`/`Deserialize` become `value.to_json() -> Result<String, Error>` and `Type::from_json(s: &str) -> Result<Type, Error>` only for a concrete, lifetime-free wrapped value whose recorded impl proves the exact serde trait under the pinned feature set. Instantiate the trait through `serde_json`, not by exposing a generic serializer/deserializer object to Rune. `serde_json` is presently a **dev** dependency of the production adapter; make it an explicit optional normal dependency of the generated feature if both pins compile with it, while the no-default hand-written build remains lean. Do not assume that one serde impl implies its partner, that deserialization is context-free, or that a generated owner has the same feature-set impl at both pins.

The JSON input is script-controlled. Check its byte length against an inclusive named bound before parsing. Serialize through a bounded `serde_json::Serializer` writer whose `write` refuses before its cumulative byte count would exceed that bound; never create an unbounded full JSON string and check afterward. Route potentially expensive work through the existing engine boundary, preserving the callback re-entry and panic rules. Map serde failures to a specific catchable error, including the Polars operation and underlying cause. The bound counts UTF-8 bytes, not characters or elements; exact-bound, bound+1, overflow, non-ASCII text and invalid JSON need controls. If the existing materialize bound cannot express this without changing its meaning, define a separate documented JSON-byte bound rather than silently reusing a cell count.

This is a pinned-version interchange facility, **not** a promise that Polars JSON is stable across Polars releases or feature sets. Verify real round trips only where `Deserialize` exists and direct Rust `serde_json` succeeds, comparing values by a proven equality or a stable direct-Rust representation. A Serialize-only or Deserialize-only type can still be available on its own; do not count a round trip for it. If a type's deserializer needs a seed, cache or other context that ordinary `serde_json::from_str` does not supply, keep that impl refused by name. Probe representative enums, options, schemas and a nested/planned value at both pins before broad emission; inspect failures rather than papering over them with fixture skips.

## Other generic impls

After the same head-and-bound proof, reuse existing conversions and protocol rules rather than making a second permissive path. For operators, prove the exact left-hand borrowed/owned form, right-hand type and substituted `Output`; preserve moves, fallibility, nulls and the no-implicit-narrowing policy. A numeric scalar generic is admitted only through a proven native pair and a declared conversion policy. For `From`/`TryFrom`, prove the actual target and script-representable source, preserve outward-conversion refusals, and use the established constructor names. `FromIterator`/`Extend`/`IntoIterator`/`Iterator` require an owned or bounded iterator representation, with the whole call's materialization budget and no borrowed element escaping. `Clone`, `Debug`, `Deref`, `AsRef` and `Index` reuse the existing wrapper/protocol, projection, snapshot and lifetime contracts; a deref or index into borrowed Polars storage is not a free script reference. A trait with no useful Rune operation keeps a named contract instead of being relabelled a marker for score.

Compile direct UFCS probes before broad generation for: a passing and failing dtype alias under one generic impl; owned and borrowed arithmetic on one numeric chunked family; an operator with a projected output; one inward and one outward `From`; an iterator item containing nulls; and `Clone`/`Deref` on a concrete owner. Use a negative probe for an unresolved associated output and one for a trait with a colliding Rune protocol slot. A compile success alone does not admit a value mapping or an ownership rule.

## Validation and stop rule

Freeze the target table, v2 and 0.55.2 inventories/surfaces/results or pinned references, digests and a clean-checkout replay. Run generator self-tests, drift checks, the full v2 oracle and all three production adapter suites with fail-fast off. Each newly admitted binding with a feasible fixture gets a direct Rust comparison; report fixture failures and exclusions explicitly, including every old oracle status movement. A focused test must cover JSON equality and errors at byte boundaries, map/iterator/operator behavior, receiver reuse after a failed conversion, and no partial mutation on refusal. Measure three interleaved launch sets against the retained 0111 binary if production generated code changes, under the +5 ms budget.

Report the 732 rows by generated, proved-but-unmapped, unproved and named refusal, and split serde from non-serde. Give available callables, binding count, value-tested count, full-public and applicable denominators at both pins. If the first serde probes show that JSON is not a faithful, bounded script boundary for a broad class, stop that lane with its measured reasons and complete the independently proved non-serde lane; do not turn hundreds of rows into one-off release entries or one Markdown record per impl.

## Scope split (agreed with Codex before the implementation commit)

The first probes showed that the non-serde lane is about 20 distinct trait families (`FromIterator`, `From`, operators with scalar generic right-hand sides, `Deref`/`DerefMut`, `Iterator`/`IntoIterator`, `AsRef`, `Index`, `Clone` on generic heads, the hex/octal/binary formatters, `Extend`, `TryFrom`, `Debug`). Each needs its own value mapping and shape gate. 0112 therefore closes on the **bounded serde JSON lane** only, with its v2 and 0.55.2 proofs, tests, replay and launch checks.

The frozen target table still inventories **all 732** rows. The 345 non-serde rows are marked **`deferred to 0113, unproved`**: they are not unsupported by a failed mapping, and they are not counted available. Record 0113 takes those families together as one batch record, with per-family exact-shape gates and the shared owner/bound proof. It is not one record per trait.
