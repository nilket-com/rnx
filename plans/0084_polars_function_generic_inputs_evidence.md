# 0084 function generic inputs: evidence

Plan `dd58553`. Two generator rules chose function-level generics from script values: chained inference (a generic bounded only through another generic's item or slice element is inferred with it) and iterator-input lowering (a bare `Iterator`, `ExactSizeIterator`, `DoubleEndedIterator`, `TrustedLen` or `PolarsIterator` bound is fed from a script vector). 21 of the 30 frozen targets emitted and compiled; 4 further callables the same rules reached came with them; every miss is a named refusal.

## Gate 1: target set and audit

`probes/0084/targets.json` froze the 21 direct chained keys and the 9 iterator keys (3 owned-item, 5 borrowed-item, and `Logical::from_str_iter` on a generic owner) from the 0083 census, with canonical paths, bounds, receivers, returns, the 0083 reason and, after emission, an `audit` verdict. Chained: 15 emitted; `DataFrame::group_by` and `group_by_stable` blocked by their `GroupBy<'_>` lifetime return; `StructNameSpace::drop`, `field_by_names`, `rename_fields` blocked because `StructNameSpace` is a plain tuple struct without `Clone` and the receiver is consumed (polars-plan 0.55.2 `dsl/struct_.rs:6`); `LazyFrame::group_by` already available through the hand-written binding (adapted). Iterator: 6 emitted (the four list-builder methods with borrowed items, `ListBooleanChunkedBuilder::append_iter`, `ScanSources::gather`); `FileScanIR::gather_after_filter` refused by the release file after Codex's review: its indices must be ascending indices into the pre-filter source list and `first_file_dropped` must agree with them, Polars indexes the cached Parquet metadata directly, and `FileScanIR` does not record the pre-filter length, so a binding cannot validate the contract (polars-plan 0.55.2 `src/dsl/file_scan/mod.rs:186-218`); `ScanSources::gather` stays, since it indexes with bounds checks and returns a new value, so bad input panics without corrupting state; `FrozenCategories::new` blocked by its `Arc<Self>` return; `Logical::from_str_iter`'s four pairs stay unresolved because the family applicability engine still sets function generics aside (a separate 0083 decision). The 0083 census file is untouched; its `match_chunks` refusal is now enforced by the release file.

## Gate 2: generator rules and compilation

*Chained inference.* `unused_generic` now counts a generic as used when it appears in another generic's bound, so `I: IntoIterator<Item = S>, S: AsRef<str> | Into<PlSmallStr>` resolves through the existing `IntoIterator` rule to a script vector whose elements are carried as owned `String` (a vector element that maps to `&str` is taken by value, never a vector of borrows), and `E: AsRef<[IE]>, IE: Into<Expr> + Clone` to a vector of `Expr` taken by `support::take`. `Option<E>` (`over_with_options`) and two independent chains (`rename`) compose through the existing arms. A chained binding is fallible, since element conversion can fail, so the script receives a `Result` even where Polars returns the value directly.

*Iterator inputs.* `World::iterator_input` lowers the item: owned items build `Vec<Item>` and pass `into_iter()`, which is `Iterator`, `ExactSizeIterator` and `TrustedLen`; `&str`, `&[u8]`, `Option<&str>` and `Option<&[u8]>` build `Vec<String>`, `Vec<Vec<u8>>` or their `Option` forms into a temporary named in the binding's `pre` statements and pass `temp.iter().map(String::as_str | Vec::as_slice | Option::as_deref)`; the temporary lives for the whole Polars call, including inside a routed engine-thread closure, and no borrow reaches a script value. `support::BorrowRune` gained `Option<T>` for optional elements. Other borrowed items (`&Series`, `&Row`) are refused as `iterator of borrowed items`; `Into<(…)>` tuple targets are refused as `tuple conversion` (mechanically mappable, deliberately withheld per the plan).

*Scope and policy.* The `generic_fn` bucket token admits `generic`-bucket callables that carry function generics and nothing else; 0083's dry run showed the whole bucket would bring 30 unrelated bindings. The release file gained `[[refused]]`, consulted for methods and free functions, with `ChunkedArray::match_chunks` and `FileScanIR::gather_after_filter` and their source citations. Synthetic controls (`--self-test`, `generic-input self-test`): one and two string chains, a `PlSmallStr` chain, `Vec<Expr>` through `AsRef<[IE]>`, optional `E`, bare `Iterator<usize>`, `TrustedLen` with `Option<bool>`, borrowed `&str`, `&[u8]` and `Option<&str>`; refusals of the tuple-with-`Field` item, a return-only generic, a closure bound and a release-refused path; and the bucket staying closed without the token. Every emitted binding compiles with all features and without generated bindings (the second check). A no-op `clone()` on slice returns from 0082 was removed from the emitter while here (56 warnings gone).

Counts, 0082 to 0084: generated operations 2,065 to 2,090 (21 targets; `DataFrame::select_to_vec`, `sort`, `sort_in_place` and `row::infer_schema` also emitted under the same rules); adapted 327 to 329 (`LazyFrame::group_by`, `lit`); unsupported 1,969 to 1,942; bindings 3,904 to 3,929; oracle cases 2,057 to 2,073; refused proven pairs 287 and unresolved pairs 672 unchanged; wrappers 271 paths.

## Gate 3: behaviour and oracle

`tests/generic_inputs.rs`: `select_`, `drop_many` and `partition_by` take string vectors, the caller's vector and its elements read the same afterwards, an empty selection yields a zero-column frame, and an unknown name comes back as `ColumnNotFound` with the frame and the vector intact; `rename` takes two independent vectors, `group_by_stable`, `sort_by`, `over`, `concat_list` and `cols` take expression vectors (the `concat_list` plan is checked through its schema because a list column is outside the adapter's collectable dtypes since record 0058); the list builders take script vectors of strings, bytes and optional values, borrowed for the call, an empty vector, a `0x00 0xff` cell, and a 256 refused at element conversion, with the builders finishing to the expected lengths.

Oracle: 2,073 cases, all verified; 16 new cases, all `match` (`as_list`, `by_name`, `cols`, `concat_expr`, `concat_list`, `drop_many`, `group_by_stable`, `over`, `over_with_options`, `partition_by_stable`, `rename`, `select`, `select_to_vec`, `sort`, `sort_by`, `sort_in_place`). `DataFrame::partition_by` is excluded from the oracle by the release file: the order of its partitions is unspecified (only `partition_by_stable` is documented as order-maintaining) and the unordered policy compares rows within one frame, not a vector of frames; the exclusion was found by a run-to-run difference. Unverified (emitted, no fixture-driven case): the five list-builder methods, `DataFrame::explode`, `ScanSources::gather`; the builders are exercised by the behaviour suite instead. Tally: 1,956 match, 98 both_error, 17 both_panic, 2 row_order_differs (the two `unique` permutations), 0 fixture_failed. Value-tested paths 1,263 to 1,277; scoreboard 2,101 available (2,074 + 25 generated + 2 adapted), 1,328 value-tested, 1,942 unsupported. Chained contribution: 15 operations available, 13 value-tested; iterator contribution: 6 available, 0 value-tested by the oracle.
