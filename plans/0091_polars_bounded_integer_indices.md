# rnx 0091: bounded integer index conversion

Status: plan. Record 0090 closed at plan `90fdbbb` and implementation `1c2a95b` on `origin/main`.

## Target and source contract

The 0090 scoreboard is 2,115 script-available operations, 1,342 value-tested, and 1,928 unsupported; 178 proven receiver pairs remain refused. The 0083 function-generic census lists `convert_and_bound_idx_ca` (`polars_ops:1057`, canonical path `polars_ops::series::ops::index::convert_and_bound_idx_ca`) as unavailable because its `&ChunkedArray<T>` argument has a function-level `T: PolarsIntegerType`. Its signature is `(&ChunkedArray<T>, usize, bool) -> PolarsResult<IdxCa>`. This is **one free operation**, outside the 178-pair receiver pool. The eight already wrapped integer identities (Int8/16/32/64, UInt8/16/32/64, with `UInt32Type` represented by `IdxCa`) set a ceiling of **eight bindings**.

Pinned Polars 0.55.2 `polars-ops/src/series/ops/index.rs:12-82` maps unsigned values in `[0, target_len)` and signed values in `[-target_len, target_len)` to `IdxSize`; other values become null if `null_on_oob` is true or produce an OutOfBounds error otherwise. Existing input nulls remain null. The function asserts `target_len < IdxSize::MAX as usize`, then allocates a vector and bitmap of `ca.len()` and uses unchecked pushes. The binding must reject an invalid `target_len` **before calling Polars**, including on an empty input. The audit must prove the two `ToPrimitive` conversions are total for each admitted native integer type, so the output and validity builders receive one element per input. It must also prove that the cast to `IdxSize` occurs only with a validity bit that discards out-of-range values; no wrapped value may become valid. A compile or source-audit failure excludes that type with a cited reason.

## Binding rule

Extend 0089's exact free-instantiation gate for this key and canonical path, with the eight concrete integer types. The first argument fixes `T`; borrow its wrapper and call the public re-export (verify its spelling in the compile probe). Map script `target_len: i64` to `usize` with the existing checked narrowing, then require `target_len < p::IdxSize::MAX as usize` through a typed, operation-named error. Scope the extra guard to this exact key and parameter in the release file. It must execute before Polars allocates or reaches its assertion, including when `null_on_oob` is either value. Return the existing `IdxCa` wrapper through `PolarsResult`; preserve its null mask. Do not add a general `usize` clamp or change unrelated free instantiations.

## Gates

1. **Freeze and prove.** Record the key, canonical signature and bounds, prior surface reason, all eight proposed `(key, wrapper, T, native)` rows, and the exact source path in `probes/0091/targets.json`. Compile direct calls for each type against the pinned adapter build. Audit both signed and unsigned source branches, their unchecked pushes and validity construction, with particular attention to `i64::MIN`, `i64::MAX`, `u64::MAX`, `target_len == 0`, and the exclusive upper bound. Record each emitted or excluded row with a reason. Establish the public callee path by compiling it, not by guessing from the inventory path.
2. **Guard narrowly.** Add a release-file field or entry that names this key, path and `target_len` parameter; validate its shape and apply the exclusive `IdxSize::MAX` check to the converted `usize` before the call. A synthetic generator control must show the check on this free instantiation, no check on another listed function with a `usize` parameter, and no leakage after the scoped emission. Test negative script lengths, exactly `IdxSize::MAX`, and one less using an empty receiver; the first two must be typed refusals without a Polars assertion, and the last must be admitted without allocating a large array. Keep the generated result fallible. Run generator self-test, drift/accounting checks, and both adapter build configurations.
3. **Compare behavior.** For each emitted binding, compare Rune with the same direct Rust call on legal target lengths: in-range and out-of-range positive values, negative indices for signed inputs, null input, `target_len == 0`, both `null_on_oob` settings, and a multi-chunk receiver. Verify values **and validity**, not merely length or error kind, and assert the input remains usable. Use a Rust-backed script fixture for `u64::MAX` if the script integer cannot construct it; confirm that a truncating cast never makes it a valid index. Add paired oracle cases for all emitted bindings with usable fixtures, separating matches, both-error/panic and unverified cases. A compile-only binding is not value-tested.
4. **Reconcile cost.** Run the full all-features oracle and both adapter suites with Cargo fail-fast disabled. Reconcile the 2,115/1,342/1,928 baseline, operations, bindings, value-tested operations, unsupported operations and unchanged 178-pair pool. Retain and hash the closed 0090 binary before rebuilding; measure three interleaved 60-run cold-launch sets against the +5 ms per-record budget and preserve raw samples. Put source citations, per-row decisions, boundary results, oracle tally, hashes and launch data in `plans/0091_polars_bounded_integer_indices_evidence.md`; document the admitted call and guard in the adapter and generator READMEs.
