# rnx 0096: null-aware numeric vectors as owned script values

Status: plan. Record 0095 closed at plan `9a440a8` and implementation `cc31e15` on `origin/main`.

## Target and source contract

The 0095 scoreboard is 2,119 script-available operations, 1,363 value-tested and 1,924 unsupported. The refused proven-pair pool is 178; 624 function-generic pairs remain unresolved. `ChunkedArray::to_vec_null_aware` (`polars_core:3658`) is refused on ten proven numeric receiver pairs because its return is `either::Either<Vec<T::Native>, Vec<Option<T::Native>>>`. Six nonnumeric pairs are rejected by the recorded `T: PolarsNumericType` applicability proof. This record targets **one new operation, up to ten bindings and ten paired oracle cases**, taking only those ten numeric pairs from the refused proven-pair pool.

Pinned Polars 0.55.2 `polars-core/src/chunked_array/to_vec.rs:16-31` returns `Left(Vec<T::Native>)` exactly when `null_count() == 0`; otherwise it returns `Right(Vec<Option<T::Native>>)` through `to_vec()`. Both branches own their elements, and the branch is determined by null presence. Bind the result as an owned `Vec<Option<ScriptNumber>>`: wrap each Left element in `Some`, preserve each Right option, and apply the existing scalar return conversion (`f32` to Rune float, narrow integers to Rune integer, and 0093 checked widening for `u64`). The script can distinguish the branches' meaningful contents by whether any `None` occurs; it cannot observe the Rust enum tag, which conveys no additional value here. Do not call `to_vec()` in place of this Polars method or expose `Either` as a generic foreign type.

Polars allocates the first vector inside `to_vec_null_aware`, before the adapter converts it. Check `receiver.len()` against the existing materialize bound **before** calling Polars and before allocating the script vector. The bound is inclusive and applies to the whole result regardless of branch or chunk count; refuse with `MaterializeLimit`, naming `to_vec_null_aware` and the length/bound, if exceeded. Keep 0082's cumulative slice budget and 0077's iterator budget behavior unchanged. A value over `i64::MAX` in a `UInt64` receiver is a 0093 `ConversionError` during element read-back, with no wrapped negative or partial script vector.

## Gates

1. **Freeze and prove the branch contract.** Record all 16 family pairs, source return shapes after substitution, old refusal reasons, and proposed dispositions in `probes/0096/pairs.json`. Compile direct calls on every numeric wrapper against the pinned adapter build. Demonstrate `Left` on no-null and empty inputs, `Right` on a null-containing input, including a multi-chunk receiver. Verify the source's `null_count` choice and both branches' ownership; if a listed pair differs, exclude it with a named reason. Keep 624 unresolved function-generic pairs separate from this proven-pair pool.
2. **Implement only the exact return shape.** Add a release-file entry keyed by both `polars_core:3658` and its canonical path, with a source citation and the ten applicable numeric identities. Validate the full `Either<Vec<T::Native>, Vec<Option<T::Native>>>` shape against each concrete pair before emitting binding text; do not activate a general `Either` rule. Compose conversion from the existing scalar return mapping so `u64` remains fallible and all other types retain their documented behavior. Ensure the Polars result and both vectors are owned by the time the binding returns, including any routed call. A helper or generated pre-call step must reject over-bound `receiver.len()` before invoking Polars. Synthetic controls cover Left and Right, an empty Left, a null Right, `UInt64` overflow, exact bound and bound+1, unlisted key/path, wrong branch or native type, malformed release entry, and scope reset. A refusal must emit no binding text; an unrelated `Either` must stay unsupported. Compile both adapter configurations.
3. **Compare values and memory bounds.** For each emitted binding, compare Rune's vector length, option positions and values with a direct Rust `Either` result on no-null, null-containing, empty and multi-chunk receivers. Cover signed limits, unsigned maxima, Float32 rounding, Float64 NaN/infinity and negative zero; compare float classification and sign as well as ordinary values. On a Rust-backed `UInt64` fixture containing `i64::MAX + 1` and `u64::MAX`, verify `ConversionError` without a partial vector and that the receiver still works. Under `test-support`, lower the materialize bound to `n-1` (refused before the Polars call) and to `n` (accepted), for both Left and Right and a multi-chunk input; confirm an empty result under the production bound (the test hook uses zero to reset to that bound). The caller must still own and reuse the receiver after success or refusal. Add a paired oracle case per emitted binding, with direct behavior controls for the Right branch and high `u64` values if standard oracle fixtures reach only Left. A compile-only binding is not value-tested.
4. **Reconcile accounting and cost.** Run generator self-test and drift, both adapter suites with Cargo fail-fast disabled, and the full all-features oracle. Reconcile the 2,119/1,363/1,924 baseline, generated operations and bindings, value-tested operations, the 16 pair decisions, the refused proven-pair pool (178 to at most 168), unchanged unresolved generic pairs, and any old oracle status movement. Retain and hash the closed 0095 binary before rebuilding; measure three interleaved 60-run cold-launch sets under the +5 ms budget. Write source citations, pair and branch proofs, exact values and errors, oracle tally, binary hashes and raw launch samples in `plans/0096_polars_null_aware_numeric_vectors_evidence.md`; document the resulting vector contract in the adapter and generator READMEs.

All other Arrow arrays, buffers, borrowed array views, `with_validities`, and the function-generic and callback pools keep their current dispositions.
