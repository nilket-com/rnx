# rnx 0092: numeric left-hand subtraction with a typed scalar

Status: plan. Record 0091 closed at plan `91570f5` and implementation `e0ab92e` on `origin/main`.

## Target and source contract

The 0091 scoreboard is 2,116 script-available operations, 1,343 value-tested, and 1,927 unsupported; 178 proven receiver pairs remain refused. The 0083 census marked `ChunkedArray::lhs_sub` (`polars_core:3719`) as needing a numeric-scalar policy. Its function generic is `N: Num + NumCast`, and its owner generic is `T: PolarsNumericType`; the script has no way to name `N`. Its 16 family-census pairs are currently **unresolved** on function-level generics. Ten pairs have physical numeric wrappers (eight integers, with `UInt32Type` represented by `IdxCa`, and Float32/64); the six nonnumeric wrappers do not satisfy the owner bound. This record targets **one newly available operation and up to ten bindings**. It does not subtract from the separate 178 refused *proven* pairs.

Pinned Polars 0.55.2 `polars-core/src/series/arithmetic/borrowed.rs:836-843` converts `lhs` to `T::Native` with `NumCast::from(lhs).expect(...)`, then calls `ArithmeticChunked::wrapping_sub_scalar_lhs`. The signed and unsigned primitive kernels use `lhs.wrapping_sub(x)` (`polars-compute/src/arithmetic/signed.rs:80-82`, `unsigned.rs:68-70`); the float kernel uses ordinary subtraction (`float.rs:59-65`). Source and compile probes must confirm the path for every admitted type and null/empty receiver. Bind `N` as that wrapper's exact `T::Native`, so Polars's same-type `NumCast` is total and the script cannot induce its `expect` panic by supplying an out-of-range scalar. Integer script values narrow with a checked error; Float32 follows the existing `f64 as f32` policy, and Float64 passes directly. Preserve Polars's wrapping, float and null behavior; do not reimplement the arithmetic in the adapter.

## Binding rule

Add an exact release-file gate for key `polars_core:3719`, its canonical path and the ten numeric type identities. Apply the family applicability proof to this function-generic method, then substitute the **parameter** generic `N` structurally with that pair's native scalar and clear it only after all residual generic uses and bounds are checked. The generated instance method borrows the wrapper, passes the checked or cast scalar to Polars's `lhs_sub`, and returns a newly owned wrapper. Reject an unlisted type, a nonnumeric owner, or any surviving generic with a named reason. Do not enable `N: Num + NumCast` globally or change the other five numeric-scalar census entries.

## Gates

1. **Freeze and prove.** Record the inventory key, canonical method signature and both bounds, prior surface disposition, all 16 census pair decisions and the ten proposed `(wrapper, T, T::Native, N)` rows in `probes/0092/targets.json`. Compile direct `lhs_sub::<T::Native>` calls against the pinned adapter build for every proposed wrapper. Inspect the signed, unsigned and float kernels reached by the method, including their behavior on nulls, empty inputs, integer wrap and NaN/infinity. Classify all 16 pairs as emitted, excluded or still refused with cited reasons. Keep the 178 proven-pair pool distinct from these formerly unresolved pairs.
2. **Narrow generation.** Implement only the exact key/path/type rule. Synthetic controls cover Int8 checked narrowing, `IdxCa`, Float32 cast, same-type `NumCast`, a missing or inapplicable type, an unlisted `NumCast` method, residual `N` in another parameter or return, and scope reset after emission. A malformed release entry must fail closed before producing binding text. Compile both adapter configurations and run generator self-test and drift/accounting checks. Verify no unrelated callable or receiver pair changes disposition.
3. **Compare values.** For every emitted wrapper, compare Rune with a direct Rust `lhs_sub` on positive and negative scalar values where representable, null and empty arrays, multi-chunk input, and receiver reuse. Exercise integer overflow/underflow (including a Rust-backed `u64::MAX` receiver), refused narrow or negative-to-unsigned scalars, and Float32/64 NaN, infinity and finite rounding. Compare values and validity, not only shape; verify that a rejected scalar leaves the receiver usable. Add a paired oracle case for each emitted binding with a usable fixture and separate matches, both-error/panic and unverified cases. A compile-only binding is not value-tested.
4. **Reconcile cost.** Run the full all-features oracle and both adapter suites with Cargo fail-fast disabled. Reconcile the 2,116/1,343/1,927 baseline, generated operations and bindings, value-tested operations, unsupported operations, 16 family-pair decisions and the unchanged 178 refused proven pairs. Retain and hash the closed 0091 binary before rebuilding; measure three interleaved 60-run cold-launch sets under the +5 ms per-record budget and preserve raw samples. Write source citations, pair decisions, oracle tally, hashes and launch data in `plans/0092_polars_typed_left_subtraction_evidence.md`; document the exact scalar policy in the adapter and generator READMEs.

`lhs_div` and `lhs_rem` need separate zero and overflow audits before using this rule. The other numeric-scalar callables, function-generic candidates, callback audits, Arrow pairs, `with_validities`, and unchecked `usize as i64` audit remain open.
