# rnx 0110: proven trait implementors through wrapped Rune owners

Status: plan. The 0108 v2 baseline and 0109 move rule are closed on `origin/main` (`ec80853`, `97b51f4`). This is **one shared trait-dispatch rule**, not a record for each trait or method. The v2 Rust API at `da47b7405f0e2d188e71cce7c2d588c695f4098d` remains the target; 0.55.2 stays an active compatibility build until a separate migration decision.

## Target and admission contract

The 0109 v2 census has 6,552 script-applicable Rust callables, 3,059 available and 1,937 value-tested. Its `trait_dispatch` group contains **335 missing `trait_method` callables** with `no wrapped implementor`: 285 have an empty `implementors` list, 40 list at least one concrete or generic-base implementor, and 10 list only `blanket`. The 0.55.2 production surface has 133 `no wrapped implementor` rows. These are targets for a rule, not a promise that all will bind. The v2 cluster includes `StringNameSpaceImpl` (46), `ListNameSpaceImpl` (25), `TemporalMethods` (20), `DatetimeMethods` (16), `SeriesOpsTime` (16), `ArrayNameSpace` and `BinaryNameSpaceImpl` (15 each), plus smaller traits. One useful result is calling a Polars trait method on an already wrapped `StringChunked`, `ListChunked`, `Series`, `DataFrame` or temporal alias using the ordinary Rune method syntax.

Admit a `(trait method, receiver wrapper)` binding only when the pinned rustdoc graph proves a concrete `impl Trait for Receiver` or proves a generic impl after substituting the wrapper's exact type identity and discharging **all** bounds. Require the trait's public path, a reachable receiver type and an existing or generally admissible wrapper. Match `StringChunked`-style aliases through their canonical `ChunkedArray<Type>` identity; never infer an impl from a method name, a shared base name or a Python API entry. For blanket impls, missing/foreign associated types, unresolved bounds, ambiguous aliases, trait objects and hidden/non-public receivers, keep a named per-receiver refusal. After a pair is proven, use the existing `emit_method_with` path for argument, return, arity, callback, borrowing, movement, engine routing and refusal checks. A proven impl can still fail one of those independent checks. Preserve inherent-method precedence and the existing deref route.

## Work

1. **Repair the implementor inventory once.** Trace why rustdoc at v2 yields 285 empty lists: the 0072 extractor currently records implementations while visiting reachable types, which can miss a local extension trait implemented for a type defined in another crate. Walk the pinned rustdoc impl records by trait identity as well, then join them to reachable public traits and receiver types. Record exact `for` type, impl generics, where clauses, associated types and source crate. Reject a trait/name collision or an impl from another feature configuration. Keep raw inventory callable identities and the 0108/0109 denominator stable; if they change, explain each delta. Run the same extraction rule on the 0.55.2 adapter-narrow input. Save a machine-readable target table with each of the 335 keys, candidate implementors, proof status, bound checks and final disposition. Do not rewrite the 0108/0109 evidence bundle.
2. **Dispatch by proof, not a release-file method list.** Generalize the generator's `trait_method` branch to enumerate proven wrapped implementors (direct and generic-instantiated) and call the method through the public trait UFCS path. Resolve aliases by exact canonical identity and deduplicate equivalent receiver wrappers; emit separate bindings for genuinely distinct receiver types. Check all impl and method bounds after substitution. A blanket impl is admitted only if its receiver and every bound can be proven for a finite wrapped type; never use `blanket` itself as a receiver. Keep the existing no-implementor reason when the graph contains none and expose per-receiver reasons when a candidate fails. No `[[refused]]` entry per method: any exception must come from a shared shape rule or a cited safety contract.
3. **Probe the distinct families before broad generation.** Compile direct UFCS controls at both pins for at least: string and binary namespace methods on their chunked aliases; a list or array method; temporal/datetime on the relevant `Series` or logical chunked type; one generic `ChunkedArray<T>` impl with a passing and a failing dtype bound; and one `DataFrameJoinOps` call. Include an empty-implementor trait and a blanket-only trait as negative controls. Ensure traits with a `self` receiver use 0109's move behavior and that routed methods retain the callback/engine boundary. The controls should prove actual impl resolution, not merely compare generated text.
4. **Expand the direct Rust oracle and test the boundary.** Regenerate v2 and 0.55.2 from their pinned inventories, then compare representative values, nulls, errors and receiver reuse against direct Rust for every admitted method with a feasible fixture. Give special attention to name collisions with inherent methods, alias-equivalent wrappers, generic bounds and `&mut self`/`self` methods. A focused behavior test should exercise at least one `StringNameSpaceImpl`, one temporal method, one generic chunked trait and one negative/ambiguous case. Re-run the full v2 oracle and the three production adapter suites with fail-fast off, reconcile every status movement, and keep unordered-row policy explicit. Record callable, binding and value-tested deltas separately. If production generated files change, measure three interleaved launch sets against the retained 0109 binary under the +5 ms budget.

## Deliverables and stop rule

Commit the extractor/generator rule, inventory proof controls, target table and a compact frozen v2 evidence bundle with digests and a clean-checkout replay. The evidence must show how the 335 divide among proven pairs, emitted callables, independent conversion/refusal blockers, blanket-only rows and still-unresolved impl metadata. Quote the resulting v2 numerator over **6,552 applicable callables**, plus the full-public and value-tested views; update the denominator only if the extractor changes callable identity or exclusion, with an exact explanation. Report the 0.55.2 compatibility delta and launch measurements. If the first source probe cannot recover trustworthy implementor evidence for the large namespace/temporal clusters, stop at a documented failed proof and regroup; do not compensate with hundreds of hand-maintained method gates or individual Markdown records.
