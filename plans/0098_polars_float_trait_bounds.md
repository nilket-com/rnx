# rnx 0098: cited float trait bounds on six `ChunkedArray` methods

Status: plan. Record 0097 closed at plan `d88ed2e` and implementation `077d59e` on `origin/main`.

## Target and source contract

The 0097 scoreboard is 2,123 script-available operations, 1,367 value-tested and 1,920 unsupported. The refused proven-pair pool is 168; 576 family pairs remain unresolved. Six `ChunkedArray<T>` methods have no function-level generics but remain unresolved because the applicability engine cannot prove the external `T::Native: num_traits::float::Float` bound: `is_nan` (`polars_core:3546`), `is_not_nan` (`:3547`), `is_finite` (`:3548`), `is_infinite` (`:3549`), `none_to_nan` (`:3550`) and `to_canonical` (`:3554`). Each has exactly two unresolved receiver pairs, `Float32Chunked` and `Float64Chunked`; the other 14 aliases per method are already rejected by `T: PolarsFloatType`. This record targets **six new operations, 12 bindings and 12 paired oracle cases**. It should move the unresolved pool from 576 to 564 without changing the 168 refused proven pairs.

Pinned Polars 0.55.2 `polars-core/src/chunked_array/float.rs:1-91` defines the first five under `T: PolarsFloatType, T::Native: Float`, and `to_canonical` under the additional `T::Native: Canonical`. `f32` and `f64` implement both; `float.rs:46-67` supplies the two `Canonical` impls. The first four methods return `BooleanChunked`: `is_nan` and `is_not_nan` retain input validity, while `is_finite` and `is_infinite` run the value kernel and retain validity (`chunked_array/ops/arity.rs:148-169`). `none_to_nan` replaces nulls with valid NaNs via Arrow `set_at_nulls` (`polars-arrow/src/legacy/kernels/set.rs:16-39`). `to_canonical` maps negative zero to positive zero and every NaN payload to the canonical quiet NaN, preserving null validity (`polars-utils/src/total_ord.rs:25-49`). These methods return new owned Polars arrays in existing wrappers; no script vector or borrowed Arrow view is exposed.
