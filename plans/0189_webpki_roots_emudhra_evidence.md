# rnx 0189 evidence

Builds: release `rnx --locked` on strix (taskset -c 0-7,10-31) from HEAD
2cc4919 (`webpki-roots` 1.0.9) and from this change (1.0.10). Each build
called `http::get(url).await.map(|r| r.status)` for every TLS check host on
the incident page, 2026-10-22.

| Hosts | Chain | 1.0.9 | 1.0.10 |
| --- | --- | --- | --- |
| dv/ov/ev-g3b, dv/ov/ev-g3c, dv-g3b-noct (7) | emSign TLS G3 via emSign ECC Root CA - G3 | 200 | refused |
| the same seven with the `-aaa` Sectigo cross-sign | AAA Certificate Services | refused | refused |
| www.mozilla.org (control) | unaffected | 200 | 200 |

Before the change, rnx accepted all seven emSign-path hosts; afterwards it
refuses every affected chain and still reaches the control host. The refusal
message is reqwest's generic `client error (Connect)`. Reporting the rustls
cause (an unknown issuer) is a separate diagnostics item.

`webpki-roots` 1.0.10 drops exactly one root relative to 1.0.9, `emSign ECC
Root CA - G3`; the other emSign roots (C1, G1, ECC C3) are unaffected by this
incident and remain. Its LICENSE is byte-identical.

Notices: the root THIRD-PARTY-NOTICES.md changes only the `webpki-roots`
version. The adapters/polars, adapters/postgres and servers/http-postgres
notices were already stale before this record: they still listed Rune 0.14.2
and older musli/num packages from before the 0187/0188 pin moves. They are
regenerated by their own scripts and each passes `--check`. No test covers
those three files; adding their `--check` to the suite is a follow-up.

Root suite with this change (strix, `--locked --no-fail-fast`): 51 test
binaries, 478 passed, 0 failed, 2 ignored.
