# rnx 0083: function-level generic census and instantiation decision

Status: plan, against closed record 0082 (`23a4abe`, `f5a1a22`). This record takes the function-level generic pool before making another ownership decision for Arrow foreign types. It measures the present pool, selects concrete monomorphizations, and proves their signatures and ownership contracts before a binding record. It does not count a receiver pair as a new operation.

## Starting point

The adapter-narrow inventory has 606 callables with a nonempty `generics_canonical`; 171 are in the extractor's unsupported bucket, leaving 435 eligible callables (432 canonical paths). On the 0082 surface, those 435 partition into 113 generated, 5 adapted, 265 unsupported, and 52 internal-crate out-of-scope listings. The 265 unsupported include 74 stopped by the callback audit and 132 in the generic bucket (109 `bucket: generic`, 23 `bucket: generic (no proven instantiation)`). These groups overlap the generic *topic* but are distinct surface dispositions; none is an estimate of new operations.

Separately, the `ChunkedArray`/`Logical` applicability census has 436 eligible receiver pairs across 34 inventory keys marked unresolved because of function-level generics. That is a pair count, not 436 operations or a claim that all 34 methods can bind. The old parity map's “~100 of 164” and “~70” callback yield predates records 0079–0082 and is retired as a planning estimate. The 0082 scoreboard is 2,074 script-available operations, 1,312 value-tested, and 1,969 unsupported; the 287 refused *proven* receiver pairs form a separate pool.

## Decision to make

For each eligible, unavailable callable with function generics, separate four questions: (1) can a concrete type be chosen from the arguments or an explicit release policy; (2) does that type have an owned Rune input and output mapping; (3) for a closure, does the 0079 invocation/mutation/sink audit admit it; and (4) on a generic owner, does the applicability engine prove the chosen receiver pair? A method may fail more than one gate. Inference-only return generics (`Series::sum<T>` and similar), callbacks needing a fresh audit, foreign Arrow values, and iterator inputs with borrowed items must remain named refusals until their own contracts are settled.

The first implementation candidate is a small family of generic iterator **inputs** with owned scalar or wrapper items, such as `ScanSources::gather`, `FileScanIR::gather_after_filter`, and the numeric/list builders whose signatures can be instantiated from a script vector. The census must check each proposed concrete type and source signature before treating it as a candidate; these names are examples, not promised bindings. An iterator of `&str`, `&[u8]`, or `&Row` needs a borrow-lifetime rule and is not admitted by the existing 0082 *return* copy rule. No callback audit entry is inferred from a generic bound alone.

## Gates

1. **Reproducible inventory census.** Add a probe under `probes/0083/` that joins the pinned adapter-narrow inventory to `surface.json` by inventory key. Report the 606/171/435 partition, current surface dispositions, generic parameter roles (argument, return-only, closure, associated type), and the separate 436-pair/34-key unresolved family census. List every candidate by key and canonical path, not just a subtotal. Fail if inventory provenance or feature set differs from the release file.
2. **Concrete-type audit.** For each proposed monomorphization, record the exact Rust type arguments, bounds and where-predicate evidence, the Rune argument and return types, whether the receiver is consumed or borrowed, and the expected generated operation and binding identities. Reject any candidate whose generic can be chosen only from a return annotation the script cannot express. Count newly available operations, added bindings on existing operations, and still-refused pairs separately.
3. **Ownership and execution probe.** Compile one representative direct method and one family-pair instantiation in an isolated probe against the pinned Polars build. For iterator inputs, prove how a script vector owns its elements while Polars consumes the iterator; exercise empty, nonempty, and bound-edge input. For any callback candidate, apply the 0079 audit and 0080 bridge controls rather than inventing a route. Record compile failures and refusals without weakening the applicability test.
4. **Decision evidence.** Write `plans/0083_polars_function_generics_census_evidence.md` with the full partition, candidate and refusal table, compile-probe results, and a bounded implementation slice for the following record. Reconcile it with the 0082 scoreboard and the remaining 287 refused proven pairs. If this record changes only probes and plans, generated files, oracle results, and launch measurements remain at their 0082 values; do not claim availability gains.

The output is an auditable implementation choice, not a projection from the 2026-09-22 parity map. Arrow bitmap, buffer and array conversions remain the other open pool, with their existing reasons intact.
