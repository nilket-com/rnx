# rnx 0081: verify narrow integer dtype bindings

Status: plan. Record 0080 is closed at plan `61354d5` and implementation `99ba4bb`. This record selects the feature-gated dtype pool from the remaining Polars parity work. It changes the adapter's measured feature set, then validates the bindings that already compile but whose oracle fixtures cannot be constructed under the current feature set.

## Why this pool next

At the 0080 tip the oracle has 156 `fixture_failed` cases. They are exactly 39 cases each on `Int8Chunked`, `Int16Chunked`, `UInt8Chunked`, and `UInt16Chunked`; both Rune and Rust setup fail because Polars cannot cast the fixture series to those dtypes. The 156 cases cover 39 canonical operation paths. Every one of those paths already has a value match on another family, so merely fixing setup should add **zero distinct value-tested operations** to the scoreboard. It should add up to 156 verified binding cases and expose whether the narrow-family implementations actually agree with Rust. That is a quality gain, not an availability claim.

The alternative proven-pair pool has 337 refused proven pairs across 49 inventory keys, mostly involving Arrow bitmap, array or bare-slice types, so it first needs a mapping and ownership decision. The older parity map's function-level generic yield predates the 0079–0080 callback census and cannot be treated as a current estimate. The narrow dtype pool has a precise failing set and a direct Polars feature route. The next record after 0081 can choose between the remaining two using a fresh census.

## Decision and scope

Enable Polars 0.55.2's `dtype-i8`, `dtype-i16`, `dtype-u8`, and `dtype-u16` features in the adapter's facade dependency. The local Polars 0.55.2 manifest propagates each feature to `polars-core`, `polars-io`, `polars-lazy`, `polars-ops`, and `polars-time` as applicable. Keep all four together so the adapter's public feature set, its oracle fixture setup, and its rustdoc inventory describe the same build.

Do not infer a larger coverage denominator from the old `0.55.2-adapter` inventory. Extend the 0072 inventory runner with a named `adapter-narrow` configuration (`lazy`, `csv`, `parquet`, and the four dtype features), a separate lock and output directory, and recorded resolved features. Preserve the 0080 inventory and surface as baselines. Run extraction under the pinned nightly and compare callable identities and statuses against the prior adapter configuration. Point the generator and its drift test at the new inventory, with a release provenance check that rejects the old feature configuration. Regenerate bindings, fixtures, oracle harness, and surface from the new inventory; handle newly reachable callables under the existing emission rules, reporting each new or refused operation. A feature-only change must not silently expand the denominator while using the old inventory.

No callback rule, route, or oracle comparison policy changes belong in this record. The four narrow aliases must remain the same script types. `BinaryOffsetChunked` is outside this feature decision; it has no current fixture failures in the 0080 results. Adjacent 0.54.4 and rc2 release configurations stay unchanged.

## Gates

1. **Feature and fixture control.** First reproduce all 156 setup failures on the 0080 binary and inventory. Build the adapter with the four dependency features in an isolated trial; construct each of the four series through the exact generated fixture recipe and confirm its dtype, values, null placement, and conversion to its `ChunkedArray` alias. Then make the feature set permanent. A script control reads a value from each narrow alias and compares its dtype. Builds with all adapter features and with `--no-default-features` must pass.
2. **Inventory and emission.** The new rustdoc run must record the four resolved dtype features and complete all activated Polars crates. Compare the old and new callable identities before generation, naming the denominator delta; no old callable may disappear without a reason. The generator's provenance and drift checks use the new inventory. Its 0079 callback audit and 0080 post-emission assertions still pass. Reconcile generated, adapted, unsupported, out-of-scope, binding, and pair totals, separating changes caused by feature reachability from the 156 formerly unexecutable cases.
3. **Oracle.** Run the full generated oracle. The 156 baseline case IDs must still exist unless an inventory identity change is explained by the extraction diff. Each must leave `fixture_failed`; classify its new result as `match`, `both_error`, `both_panic`, or an unapproved mismatch. Any unapproved mismatch blocks completion and is fixed or narrowly refused with a cited reason. Keep run-to-run `LazyFrame::unique` row permutations out of the claimed dtype delta. Report the new verified-case tally and value-tested operation tally separately; do not claim +39 value-tested operations when those paths were already matched elsewhere.
4. **Cost and evidence.** Run the full adapter suites with and without generated bindings, generator self-test, drift/accounting check, and the oracle. Copy and hash the 0080 release binary before rebuilding; measure cold launch against that retained binary using three interleaved 60-run sets and keep raw samples, with the parity map's +5 ms per-record budget. `plans/0081_polars_narrow_integer_dtypes_evidence.md` records exact feature/provenance pins, inventory and scoreboard before/after, all 156 transitions by alias and status, any newly reachable operations, launch samples, and remaining exceptions. Update adapter and generator READMEs to name the feature set and regenerated inventory.

## Expected result and limits

The measured target is 156 additional executable oracle cases, not a promised 156 matches. The expected change to the 0080 scoreboard's 2,061 script-available and 1,299 value-tested operations is zero from fixture repair alone; newly reachable feature-gated API may change both, and its count is deliberately determined by the fresh inventory before implementation. If the feature build or extraction is incomplete, report it as a failed gate rather than presenting the old inventory under a new feature label.

This record does not address mapping-refused proven pairs, other dtype features, function-level generic instantiation, or broader Polars full-feature parity.
