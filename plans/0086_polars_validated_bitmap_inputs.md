# rnx 0086: validated validity bitmap inputs

Status: plan. Record 0085 closed at plan `7d2ed51` and implementation `bdc6a45` on `origin/main`. This record takes the input side of the validity-bitmap mapping while keeping the Arrow object hidden from Rune. The script supplies owned `Vec<bool>` masks; the binding checks their lengths and builds the Arrow `Bitmap` before Polars sees it. The 0085 bitmap-return rule remains restricted to its two listed paths.

## Measured target and source contract

The 0085 surface has 2,103 script-available operations, 1,330 value-tested, 1,940 unsupported, and 255 refused proven receiver pairs. Four currently unavailable `ChunkedArray` operations account for **41** of those pairs: `set_validity` (`polars_core:3695`, 15 of 16 aliases after excluding Struct), `with_validity` (`polars_core:3696`, 15 of 16), `from_vec_validity` (`polars_core:3587`, 10 numeric aliases), and `from_bitmap` (`polars_core:3591`, Boolean only). This is a ceiling of four new operations and 41 bindings, not 41 operations. Freeze the actual 0085 rows before editing; report any pair that fails a later gate rather than silently lowering the denominator.

Polars 0.55.2 `polars-core/src/chunked_array/mod.rs:618-639` checks that a `Some` mask has the receiver's total length, splits it across chunks, refreshes `null_count`, and rejects Struct receivers. `polars-core/src/chunked_array/from.rs:186-194` passes numeric values and the mask to `to_array`; `polars-core/src/chunked_array/mod.rs:1048-1068` constructs a `PrimitiveArray`, whose `polars-arrow/src/array/primitive/mod.rs:465-477` constructor checks equal lengths. `polars-core/src/chunked_array/from.rs:219-225` makes Boolean values directly from a bitmap. Check these pinned contracts against the compiled source in the audit, including empty inputs and the exact applicability of each alias. The binding should make an unequal length a typed script error before calling Polars, even where Polars would panic.

Do not include the other bitmap inputs in this record. `ChunkedArray::with_validities` (`polars_core:3496`) changes each chunk's mask but does not recompute the cached `null_count` (`polars-core/src/chunked_array/ops/chunkops.rs:219-228`); validating lengths alone would leave the receiver inconsistent. `StructChunked::with_outer_validity` needs a separate single-chunk and field/null-propagation audit. Arrow arrays, `Column` and `SeriesTrait` validity methods, and unrelated `Bitmap` parameters remain refused.

## Input and failure rule

Use a path-scoped release-file allowlist for these four canonical methods. Map only their `Bitmap` input to an owned script `Vec<bool>` and compose with `Option<Bitmap>`; `None` means no validity mask, while `Some([])` remains an explicit empty mask. `from_bitmap` interprets bits as **values**, not null validity. The script vector stays readable after the call, including a failed call. Materialize the immutable bitmap with bit order preserved and with the 0085 `materialize_limit()` checked before allocation; do not transfer a Rune borrow into Polars or expose an Arrow wrapper. If a call converts more than one bitmap, the bound must be cumulative across the binding call.

For `set_validity` and `with_validity`, require a `Some` mask's length to equal the receiver's total length before mutation or consumption, on every admitted alias. For `from_vec_validity`, compare the mask with the numeric values vector before construction. An absent mask has no length constraint. A mismatch or materialize-bound refusal is a typed adapter error naming the operation and lengths/bound; no partial mutation is visible. Keep the existing receiver semantics: `set_validity` mutates in place and returns unit; `with_validity` returns a new wrapper under the generator's established consumed-receiver policy. `from_vec_validity` and `from_bitmap` return new wrappers. Do not broaden the rule to nullable values, Arrow arrays, or any method whose precondition cannot be checked from the script inputs and receiver.
