# rnx 0111: Rust traits at the Rune protocol boundary

Status: plan. Record 0110 is closed on `origin/main` at `3c8c2f5`. The target remains the pinned Polars v2 Rust API (`da47b7405f0e2d188e71cce7c2d588c695f4098d`), with 0.55.2 as an active compatibility build. This is one shared protocol rule, not a list of per-type or per-method gates.

## Scope and denominator

The 0110 v2 census has 6,552 applicable callables, 3,312 available and 2,132 value-tested. Its `protocols` batch has 312 missing rows. **303** are foreign trait impl rows: Hash 165, TrivialClone 106, PartialEq 12, Drop 5, Flags 4, PublicFlags 4, FromStr 2, PartialOrd 2, and one each of TryFrom, Ord and Write. The other **nine** are trait methods refused because their trait has no public path (`ByteSource`, `WritableTrait`, `RoundSeries`); their census cause is grouped with protocols, but they are not foreign protocol impls. Audit all 312 keys, and keep those nine separate. Do not turn a private trait into a public Rune path merely to clear this batch.

`core::clone::TrivialClone` is an unstable compiler optimization marker, not an independent clone operation: core says its `Clone::clone` is equivalent to copying, and the trait itself has no method (`core/src/clone.rs`, at the pinned host toolchain, lines 253–283). Classify its 106 rows as markers apart from the applicable denominator, as `Copy` already is. `Drop`'s five impls likewise run when an owned wrapper is dropped; there is no script-callable `drop` protocol to bind. Mark those apart only after proving that normal wrapper destruction runs the Rust destructor exactly once, including a moved value. Cite the Rust trait contracts in the census. If that proof fails, leave Drop missing rather than silently reducing the denominator. Keep full-public, applicable, marker, available, and value-tested counts side by side; the conditional denominator after both marker decisions is 6,441, not a presupposed success figure.

## Shared admission rule

Dispatch from the canonical Rust trait identity, exact impl receiver identity, signature and mapped Rune protocol. Reuse an existing wrapped owner and its type/alias proof. Before emitting, validate the trait's parameter and return shapes, bound substitutions, Rune registration slot, and any pre-existing hand-written implementation. Reject unproven generic impls and conflicting registrations by name. Preserve existing operator, From, Clone, Display and Debug routes. The surface must record each of the 312 rows as generated, marker, independently refused, or still unresolved, with one reason per refusal.

For `PartialEq`, keep the existing `PARTIAL_EQ` behavior for `==`. Where the same receiver has a proven Rust `Eq` impl, also install Rune's **`EQ`** protocol using the same Rust equality operation, unless an equivalent hand-written EQ already owns that slot. Rune 0.14.2 uses `EQ`, rather than `PARTIAL_EQ`, to compare `HashMap` keys (`rune/src/hashbrown/table.rs:287–335`). The Rust `Eq` row remains a marker: the actual callable is equality, while the marker justifies total equality. Do not infer `Eq` from `PartialEq` or `StructuralPartialEq`.

Map a proven `Hash` impl to Rune `HASH` with the native protocol signature `(&Wrapper, &mut rune::runtime::Hasher) -> ()`, invoking the Rust `Hash::hash` implementation on the contained value. Admit it as a map-key capability only when Rune `EQ` for that receiver is installed from the same Rust equality semantics. A Rust `Hash` owner without `Eq` remains a named refusal rather than a hashable key with incomplete equality; count that class separately (the inventory currently lists 39 such owners). `Hasher` is the current Rune map hasher and implements `core::hash::Hasher` (`rune/src/runtime/hasher.rs`). Hashes must agree for Rust-equal values under the **same hasher state**. Rune maps use a random state, so no numeric hash value is promised across maps or runs. Keep this separate from record 0094's categorical hash-token contract.

Map admissible `PartialOrd::partial_cmp` to `PARTIAL_CMP` and `Ord::cmp` to `CMP`, returning Rune's registered `core::cmp::Ordering` (or `Option<Ordering>`) exactly as the Rust call does. Use Rust's `None` for unordered partial comparisons; do not synthesize a total order. Check the existing `PARTIAL_EQ`/`EQ` slots and collisions before installing either comparison. `FromStr` may become a `parse`-style associated constructor only where `Self::Err` can be converted into a specific catchable Rune error without hiding failure or panicking. Decide the constructor name by the existing `From`/`TryFrom` naming rules and preserve receiver ownership. The one `TryFrom<StructArray>` row requires an independently mapped input and remains refused if that Arrow value has no script representation.

`Flags` and `PublicFlags` are bitflags traits with methods, not markers: inspect the pinned signatures and expose a shared, safe value operation only if its input/output and invariant are proven. Otherwise retain named refusals. `Write` is a mutable I/O trait; admit only if ownership, byte input, write count, error conversion and routing satisfy the existing boundary. Do not count it as a marker or emit a generic protocol just because Rust implements it. The nine no-public-trait-path methods remain refused unless an already public inherent equivalent is shown and recorded as an adaptation, with no denominator change from a private path.

## Proof and validation

1. Save a machine-readable table for all 312 target keys with trait, owner, signature, prior reason, proof outcome, protocol slot or marker contract, and final disposition. Prove `TrivialClone` and Drop marker treatment from pinned Rust source and wrapper behavior. Include the 0.55.2 rows under the same rules and preserve both inventories' callable identities; explain any denominator movement exactly.
2. Compile minimal native Rune controls for `PARTIAL_EQ` versus `EQ` in a `HashMap`, `HASH` through a real map lookup, `PARTIAL_CMP`/`CMP` with less/equal/greater and unordered values, and a fallible `FromStr` constructor. Negative controls must cover Hash without Eq, an unsupported signature, a protocol slot already taken, a generic or wrong owner, and a foreign input that lacks a value mapping. Mutating the admission rule should make the matching control fail.
3. Compare direct Rust and script behavior on distinct and equal values, map insertion/retrieval/replacement, sets if exposed by Rune, errors, ordering, and receiver reuse. Use a deterministic recording hasher in a Rust unit control to compare the generated Rust hash call with direct `Hash::hash` on the same value; test Rune map behavior separately under its own state. Do not compare independent random-state hash numbers. Exercise a destructor exactly once for owned and moved values before classifying Drop as a marker. Give each newly admitted callable a feasible direct-Rust oracle case; record fixture failures and why any are infeasible.
4. Regenerate v2 and 0.55.2 from pinned inventories, run generator self-tests and drift checks, full v2 oracle and all three production adapter suites with fail-fast off. Reconcile every old oracle status move, including approved row-order variation. Replay the frozen census and target table from a clean checkout with digests, without rewriting 0108–0110 bundles. If production generated code changes, measure three interleaved launch sets against the retained 0110 binary under the +5 ms budget.

Report available callables, generated bindings and value-tested operations separately. The main yield is useful Rust value behavior in Rune collections and comparisons; a lower numerator with explicit marker and safety decisions is preferable to treating all 312 rows as bindable methods.
