# rnx 0099: owned numeric chunk snapshots

Status: plan. Record 0098 closed at plan `4a2914d` and implementation `506d8b8` on `origin/main`.

## Target and source contract

The 0098 scoreboard is 2,129 script-available operations, 1,373 value-tested and 1,914 unsupported. The refused proven-pair pool is 168; 564 family pairs remain unresolved. `ChunkedArray::chunks` (`polars_core:3681`) has 16 refused proven pairs because its return is `&Vec<ArrayRef>`, whose elements resolve to foreign `Box<dyn polars_arrow::array::Array>`. This record targets the **ten numeric pairs** (Float32/64, Int8/16/32/64, UInt8/16/32/64, including the `IdxCa` alias): one new operation, up to ten bindings and ten paired oracle cases. If all ten emit, the refused proven pool falls to 158; the six nonnumeric pairs and the 564 unresolved generic pairs keep their dispositions.

Pinned Polars 0.55.2 `polars-core/src/chunked_array/mod.rs:479-481` returns a borrow of the actual chunk vector. The numeric datatype macro at `polars-core/src/datatypes/mod.rs:181-227` gives each selected `T` a `PrimitiveArray<T::Native>` Arrow array. Preserve the result's two observable dimensions as an owned `Vec<Vec<Option<script number>>>`: the outer index identifies the original chunk, including empty chunks, and the inner vector contains that chunk's values and nulls in order. Use the existing scalar read-back rule (`f32` to Rune float, narrow integers to Rune integer, `u64` checked by 0093); do not expose `ArrayRef`, `PrimitiveArray` or borrowed storage to the script. A result must remain usable after the source chunked array is dropped or mutated.

Use the existing materialize limit as a **single inclusive budget for outer chunk slots plus inner cell slots**. After borrowing Polars's chunk list, check `n_chunks + len` with checked arithmetic before allocating either script vector; overflow or a total above the bound is `MaterializeLimit`, naming `chunks`, both counts and the bound. `chunks()` itself only returns a borrow and does not allocate. Every copied chunk is also counted during conversion, so the limit cannot reset per chunk or be bypassed by a bad length assumption. Thus even an array of many empty chunks is bounded. This is a copy budget for one binding invocation, independent of 0082's cumulative slice budget and 0077's iterator budget.
