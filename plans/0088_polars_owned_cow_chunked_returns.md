# rnx 0088: owned `Cow` chunked-array returns

Status: plan. Record 0087 closed at plan `3880625` and implementation `783a8d7` on `origin/main`. This record admits a small return shape from the foreign-type pool: a `Cow` whose inner type is already a wrapped `ChunkedArray`. Rune receives an owned wrapper in both the borrowed and owned Rust branches; no Rust borrow or Arrow array crosses the binding boundary.

## Measured target and source contract

The 0087 surface has 2,108 script-available operations, 1,335 value-tested, 1,935 unsupported, and 196 refused proven receiver pairs. Three inventory keys account for **18** of those pairs: `ChunkedArray::rechunk` (`polars_core:3434`) on 16 aliases, and the List (`polars_core:3611`) and Struct (`polars_core:3641`) implementations of `ChunkedArray::to_physical_repr` on one alias each. They are currently unbound because their returns are `Cow<Self>`, `Cow<ListChunked>` and `Cow<StructChunked>`. These are **three callables, two operation names, and at most 18 bindings**. If all emit, the 196-pair pool would fall to 178 before unrelated changes.

Pinned Polars 0.55.2 `polars-core/src/chunked_array/ops/chunkops.rs:162-182` returns `Cow::Borrowed(self)` for one chunk or `Cow::Owned` after concatenating multiple chunks; it preserves the flags it retains from the receiver. The `object` panic branch is behind a feature absent from the adapter's resolved feature set. `polars-core/src/chunked_array/list/mod.rs:47-82` returns a borrowed List when its inner dtype is already physical, otherwise constructs a physical List, potentially rechunking; `polars-core/src/chunked_array/struct_/mod.rs:138-170` similarly returns a borrowed Struct or constructs a new one from physical fields, propagating outer validity. The source audit must verify those exact contracts and the alias-specific wrapper/`Clone` requirements before emission. The change in logical dtype for an owned physical result is intentional Polars behavior and must be preserved, not disguised as an unchanged receiver.

## Ownership rule

List these exact inventory keys and canonical paths in the release policy. Admit only a `Cow<WrappedChunkedArray>` return for them. Call Polars while the receiver borrow is valid; then convert with `into_owned()` **inside the binding call** and wrap the resulting `ChunkedArray` before returning to Rune. In the borrowed branch, `into_owned()` clones the chunked-array wrapper; in the owned branch it moves the value. Script code must be able to retain the result after the receiver is dropped or changed. The method leaves its receiver unchanged. The existing materialize limit governs vectors copied into Rune and is not a new row-count limit for native Polars wrapper results; do not introduce a partial row copy to satisfy it.

The rule does not admit `Cow<Field>`, `Cow<Series>`, borrowed Arrow arrays, or other `Cow` returns. It also does not alter Polars's `rechunk_mut` or `Series::rechunk` semantics. Keep all unlisted foreign-type refusals visible in the surface.

Classify each pair as candidate, excluded with cited reason, or still refused before emission. Reconcile pair, callable and operation counts separately.
2. **Narrow generation.** Implement the key-and-path-scoped `Cow<WrappedChunkedArray>` return rule in ordinary and instantiated-family emission, clearing its scope on all exits. The generated call must finish `into_owned()` before a borrowed result can leave an engine closure, where routing is used. Synthetic controls cover borrowed and owned `Cow` results, `Cow<Self>` after family substitution, the two concrete wrapped returns, and refusal of an unlisted `Cow<Wrapped>` and `Cow<Field>` or `Cow<ArrowArray>`. Compile emitted pairs with all features and without generated bindings; assert that no unlisted callable changes disposition.
3. **Behavior and oracle.** For `rechunk`, test a single chunk, a nullable multi-chunk receiver, and an empty receiver. Compare exact values, null positions, dtype, chunk counts and retained flags where observable; verify the original receiver is unchanged. Keep both a borrowed-branch and owned-branch result after the source wrapper goes out of scope. For List and Struct, exercise already-physical (borrowed) and logical-inner/field (owned conversion) fixtures, including outer nulls, and compare result dtype and values with direct Rust. Test an invalid or failing conversion if the pinned source admits one, and ensure the receiver remains usable after an error or unwind. Generate paired Rune/Rust oracle cases for every emitted binding with a usable fixture; count value matches separately from both-error/panic and unverified cases. A borrowed-only fixture does not prove the owned branch, so retain the direct probe even if the oracle can cover only one branch.

Reconcile the 2,108/1,335/1,935 baseline, all 18 pair outcomes, operations, bindings and value-tested operations. Write source citations, branch-probe results, audit rows, tests, hashes and launch data to `plans/0088_polars_owned_cow_chunked_returns_evidence.md`, and document the owned-wrapper contract in the adapter and generator READMEs.

The other refused Arrow array returns and `with_validities` retain their current reasons. The 0083 function-generic family, numeric-scalar and callback decisions remain separate. The unchecked `usize as i64` paths noted in 0087 remain a future generator audit and do not expand this record.
