# rnx 0100: owned Boolean, string and binary chunk snapshots

Status: plan. Record 0099 closed at plan `4d94ca5` and implementation `77a0b42` on `origin/main`.

## Target and contract

The 0099 scoreboard is 2,130 script-available operations, 1,374 value-tested and 1,913 unsupported. The refused proven-pair pool is 158 and the unresolved generic pool is 564. `ChunkedArray::chunks` (`polars_core:3681`, `polars_core::chunked_array::ChunkedArray::chunks`) still refuses six receiver pairs. This record targets **four**: `BooleanChunked`, `StringChunked`, `BinaryChunked` and `BinaryOffsetChunked`. The List and Struct pairs stay refused. Four emitted bindings should add four paired oracle cases and make this already-available operation value-tested on four more receivers; distinct available and value-tested operation counts need not rise. The refused proven-pair pool should fall to 154, with unresolved generics unchanged.

Pinned Polars 0.55.2 `polars-core/src/chunked_array/mod.rs:478-481` returns a borrow of the actual chunk vector. `polars-core/src/datatypes/mod.rs:229-232` maps these four owners to `BooleanArray`, `Utf8ViewArray`, `BinaryViewArray` and `BinaryArray<i64>` respectively. Their `iter()` methods return optional values with validity in `polars-arrow/src/array/{boolean,binview,binary}/mod.rs`. Preserve each chunk boundary, including an empty chunk, and each null. Return an owned `Vec<Vec<Option<bool>>>` for Boolean, `Vec<Vec<Option<String>>>` for String, and `Vec<Vec<Option<Vec<i64>>>>` for both binary owners, using the adapter's established byte-as-script-integer mapping. The returned snapshot must outlive its receiver. Binary data must remain raw bytes, including zero and non-UTF-8 values; string data remains validated UTF-8 from `Utf8ViewArray`.

Extend 0099's inclusive materialize budget to the **whole copied result**. Count one slot per outer chunk, one per cell (null or non-null), and, for string or binary values, one per payload byte. Use checked arithmetic and reject a total above the configured bound before allocating either vectors or owned payloads. Name the operation, chunk count, cell count, byte count and active bound on overflow or refusal. Count every copied payload byte again while materializing so a bad preflight assumption cannot evade the bound. This is one cumulative invocation budget, never reset per chunk or cell. A byte count is intentional for UTF-8 strings; it does not count Unicode scalar values. The Boolean case has zero payload bytes.

## Gates

1. **Freeze the six remaining pair decisions and prove the four array mappings.** Record all six aliases, canonical identities, old refusals, expected Arrow array type and proposed disposition in `probes/0100/pairs.json` using the retained inventory and 0099 surface. Compile direct calls and downcasts under the pinned build. Probe two chunks with a null, an empty receiver and an explicit empty chunk; for binary include zero and non-UTF-8 bytes, and for string include multibyte UTF-8. Explain why List and Struct need separate nested-value policies and keep their named refusals. Do not infer boundaries from a flattened iterator.
2. **Admit only the four cited pairs.** Extend the release-file `chunk_snapshots` policy with exact `(owner identity, Arrow type, output kind)` entries and a source citation, or add an equally narrow cited policy if its shape demands it. Before emitting any binding text, require the same exact `&self -> &Vec<ArrayRef>` signature, empty parameters and method generics, `ChunkedArray<T: PolarsDataType>` owner, and a listed pair with the exact Polars datatype-to-array mapping. Fail closed for missing citation, duplicate or mispaired entry, altered receiver/return/parameters, wrong key or path, unlisted owner, and an unscoped Arrow return. Downcast safely and give a typed conversion error naming `chunks` and the expected array on an unexpected type. Finish the copy within the borrow and return only owned script values. No global `ArrayRef` rule.
3. **Compare values, validity, ownership and bounds.** Direct Rust tests compare each script snapshot with `chunks()` for all four owners: outer and inner lengths, positions of nulls, values and byte-for-byte payloads. Include one and two chunks, empty receiver and explicit empty chunk, result surviving a dropped receiver, Boolean values, multibyte text, empty text, empty bytes, zero bytes and non-UTF-8 bytes. Test a mixed multi-chunk result whose total is `chunks + cells + bytes`: bound `total - 1` refuses and bound `total` accepts; a payload individually below the bound but cumulatively over it must refuse without a partial result, with the receiver reusable. Direct helper controls must cover checked-add overflow for chunk/cell/byte totals and a wrong Arrow downcast without huge allocation. Add one paired oracle case per emitted pair, with a Rust formatter that preserves chunk and null structure. A compile-only binding is not value-tested.
4. **Reconcile accounting and cost.** Run generator self-test and drift, both adapter suites with Cargo fail-fast disabled, and the full all-features oracle. Reconcile all six pair decisions, four bindings, new oracle cases, distinct operation counts, refused-pair and unresolved counts, and any old oracle status movement. Retain and hash the closed 0099 binary before rebuilding; measure three interleaved 60-run cold-launch sets under the +5 ms budget. Put source citations, exact budget/error examples, oracle tally, binary hashes and raw launch samples in `plans/0100_polars_scalar_chunk_snapshots_evidence.md`; update the adapter and generator READMEs for the extended snapshot contract.

List and Struct chunk snapshots, other Arrow array and buffer returns, and the function-generic and callback pools retain their dispositions.
