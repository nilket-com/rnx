# rnx 0082: borrowed slices in proven Polars pairs

Status: plan. Record 0081 is closed at plan `9b5307b` and implementation `c993cad` on `origin/main`. This record takes the mapping-refused proven-pair pool first, but makes one ownership decision at a time. It targets the bare-slice subset; Arrow bitmap and array objects remain a separate decision.

## Measured starting point

The 0081 `surface.json` has 337 proven pairs refused after family applicability, across 49 inventory keys. The reason text `bare slice` appears on 51 of those pairs. They cover six operations with no binding (`ChunkedArray::min_binary`, `max_binary`, `downcast_slices`, `struct_fields`, `cont_slice`, `data_views`) and six already generated on other receivers (`for_each`, `iter`, `no_null_iter`, `get`, `first`, `last`). The six unbound operations are the upper bound on newly script-available operations from this record; the other pairs expand receiver coverage, not operation coverage. The plan does not assume all 51 will compile. Every pair's final status remains in the applicability census.

The refusal shapes are concrete: numeric `&[T::Native]` returns and iterator items, binary `&[u8]` returns and iterator items, `Option<&[u8]>`, `&[Field]`, and a callback parameter `&[u8]`. The current generator refuses these as borrowed slice returns or callback inputs even when the family applicability engine proves the pair. A Rune result cannot borrow from a Polars receiver once the binding returns; a callback cannot safely carry Polars's borrowed slice into Rune's independent VM. Those are ownership boundaries, not applicability failures.

## Ownership rule

For an immutable borrowed slice that is a Rust return, copy each scalar into an owned Rune vector before the engine-thread call ends. A byte slice is a vector of integer byte values; numeric slices use the same Rune integer/float conventions as existing scalar returns, and `&[Field]` becomes a vector of cloned Field wrappers. Preserve `Option` and `Result` structure; `None` is not an empty vector. The script owns the result and may keep it after the receiver is dropped. Never expose a Rust reference or an Arrow buffer as a Rune borrowed value.

For an iterator whose items are immutable borrowed slices, drive it on the engine thread and copy each item into a nested vector, preserving order, empty slices, and null/option structure. Apply the existing `materialize_limit()` to the outer item count and a separate cumulative element count across all inner slices, checked before each copy. A direct slice return uses the same cumulative bound. The bound applies to elements, not bytes of a formatted representation, and refuses before allocating an oversized result. The refusal is a typed adapter error with the operation and bound; no partial vector is returned. Use a test-support override to exercise the exact boundary without large allocations.

For an immutable borrowed slice passed to a callback, copy it into an owned Rune vector before calling `support::callback::bridge`; the script receives a snapshot and cannot mutate the Polars storage through it. Keep the 0080 callback guard, budget, typed unwind and routed engine boundary. If a callback returns the wrong type or fails after earlier invocations, the outer binding reports `CallbackError` and the receiver remains usable. A mutable slice is not admitted by this rule; it still needs an audited write-back contract.

The mapping is admitted only for element types with an existing script scalar or wrapper conversion. Arrow `Bitmap`, `ArrayRef`, `PrimitiveArray`, `BinaryArray` and other Arrow objects are not silently converted through Debug or opaque bytes. The release file records any family-specific exclusions with the source reason and the census records the pair refusal after emission.

## Gates

1. **Inventory and mapping audit.** Freeze the 337 refused proven pairs and the 51 bare-slice subset by key, alias and reason from the 0081 surface. For each of the 51, record the concrete substituted Rust signature, the element conversion, whether the slice is a direct return, iterator item, option, or callback input, and whether the owner guarantees the borrow lasts through the copy. Mark each pair `candidate`, `excluded` with a cited reason, or `still refused` before emission. Count distinct operations and bindings separately. The six unbound operation names above are the maximum availability yield.
2. **Emission and ownership.** Extend the generator's return, iterator and callback-input mapping with the immutable-slice rule. The helper copies under the two bounds, preserves nested and optional shapes, and returns owned Rune values. Generated calls that need the receiver borrow run the copy inside `engine::run`, not after its closure returns. Add synthetic emitter controls for `&[i64]`, `&[u8]`, `Option<&[u8]>`, `&[Field]`, iterator items `&[T]`, and callback `&[u8]`; a mutable slice remains refused. Compile every emitted family pair as the second applicability check, and reconcile the 51 dispositions with actual bindings. Existing callback audit and route assertions remain in force.
3. **Behavior and oracle.** Use real Polars fixtures for a contiguous numeric array, a rechunked multi-chunk array, binary cells with zero and non-UTF-8 bytes, and a struct with two fields. Test ownership by keeping a returned vector after the source wrapper is dropped; test exact bound and one-over-bound for direct and nested slices, including an empty inner slice. A binary callback case checks a byte snapshot and failure propagation without changing the receiver. Generate paired Rune/Rust oracle cases for every new binding with a fixture and structural comparator; report value matches separately from both-error/panic and unverified cases. Do not count a new binding as a newly available operation when its callable already had another receiver.
4. **Evidence and cost.** Run generator self-test, drift/accounting checks, the adapter suites with and without generated bindings, and the full oracle. Reconcile the scoreboard from the 0081 baseline (2,065 script-available, 1,304 value-tested, 1,978 unsupported), listing six target operations individually and all refused pairs by reason. Retain and hash the 0081 release binary before rebuilding; measure cold launch in three interleaved 60-run sets against it, with the parity map's +5 ms per-record budget and raw samples kept. `plans/0082_polars_borrowed_slice_bindings_evidence.md` records the mapping decision, source citations, pair and operation counts, oracle outcomes, launch samples, and remaining 337-pair pool. Update the adapter and generator READMEs for the owned-slice contract.

## Limits

This record does not promise +51 operations. Its upper bound is six newly available operations, plus up to 51 newly mapped family bindings. Arrow bitmap and array values, function-level generics, mutable slices, and any callback invocation without the 0079 audit remain refused. Their reasons stay visible in `surface.json` for the next record.
