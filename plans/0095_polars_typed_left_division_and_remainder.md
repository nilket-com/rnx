# rnx 0095: typed left-hand division and remainder

Status: plan. Record 0094 closed at plan `d42f4b0` and implementation `c6c7eab` on `origin/main`.

## Target and source contract

The 0094 scoreboard is 2,117 script-available operations, 1,361 value-tested and 1,926 unsupported; 178 proven receiver pairs remain refused and 656 family pairs unresolved. The 0083 census placed `ChunkedArray::lhs_div` (`polars_core:3722`) and `lhs_rem` (`polars_core:3723`) in the numeric-scalar policy pool. Each has 16 unresolved family pairs. The ten physical numeric wrappers should be applicable; the six nonnumeric wrappers should be excluded on the owner bound. This record targets **two newly available operations, up to twenty bindings and twenty paired oracle cases**. It does not draw from the 178 refused *proven* pairs.

Pinned Polars 0.55.2 `polars-core/src/series/arithmetic/borrowed.rs:845-856` first converts the function generic `N: Num + NumCast` to `T::Native` with `NumCast::from(lhs).expect(...)`, then calls `ArithmeticChunked::legacy_div_scalar_lhs` or `wrapping_mod_scalar_lhs`. Reuse record 0092's exact `T::Native` table and same-type `NumCast` proof: bind `N` to the listed wrapper's native scalar, never infer an independent type from the script integer or float. Script inputs use the existing checked narrow conversions, direct `i64`/`f64`, and the documented `f64 as f32` policy. Polars computes the array; the adapter must not approximate division or remainder itself.

The zero and overflow behavior needs a separate proof before emission. For integer division, the pinned compute kernel uses floor division with a validity mask on zero denominators; for integer remainder it uses the corresponding floor modulo and masks zero denominators. The signed `FloorDivMod::wrapping_floor_div_mod` path returns `(0, 0)` for zero and handles `MIN / -1` with wrapping arithmetic (`polars-utils/src/floor_divmod.rs`). Float division is ordinary IEEE division, while float remainder uses `lhs - rhs * floor(lhs / rhs)` (`polars-compute/src/arithmetic/float.rs`), so zero, NaN, infinity and signed zero need direct checks. A mask may invalidate a zero while the kernel still evaluates its physical value; verify that no reachable debug panic or release undefined behavior occurs for **all ten** wrapper types, nulls, zero, and signed overflow. A failed safety proof excludes that pair with a named, cited reason; the expected twenty is a ceiling, not an excuse to ship an unchecked pair.

An unlisted type, swapped native, changed generic shape or residual generic is refused before binding text. Synthetic controls cover both keys and all scalar classes (`Int8`, `IdxCa`, `Int64`, `UInt64`, Float32/64), unlisted methods and types, malformed native lists, and scope reset.
