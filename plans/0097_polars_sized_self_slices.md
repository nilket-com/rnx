# rnx 0097: concrete `ChunkedArray` head, limit and tail

Status: plan. Record 0096 closed at plan `9a10a6a` and implementation `b284cd8` on `origin/main`.

## Target and source contract

The 0096 scoreboard is 2,120 script-available operations, 1,364 value-tested and 1,923 unsupported. The refused proven-pair pool is 168; 624 function-generic receiver pairs are unresolved. Three `ChunkedArray<T: PolarsDataType>` methods, `limit` (`polars_core:3499`), `head` (`polars_core:3500`) and `tail` (`polars_core:3501`), account for 48 of those unresolved pairs: each has the sole method-level bound `Self: Sized` and each of the 16 receiver families is concrete. The inventory puts the methods in the generic bucket, although no value-level generic needs inference. This record targets **three new operations, up to 48 bindings and 48 paired oracle cases**, with the refused proven-pair pool unchanged. It must not enable other function-level generics or relax unrelated family applicability rules.

Pinned Polars 0.55.2 `polars-core/src/chunked_array/ops/chunkops.rs:278-309` defines `limit(n)` as `slice(0,n)`, `head(Some(n))` as `slice(0,min(n,len))`, `head(None)` as up to 10, and `tail` analogously from the end. `slice` returns a new `ChunkedArray<T>`, sharing underlying chunk buffers for nonempty slices and constructing an empty array for the zero-length case; the script receives its existing owned wrapper and can still reuse the receiver. The method inputs are `usize` and `Option<usize>`, already covered by the adapter's checked `i64`-to-`usize` rule. Negative script lengths must fail before Polars is called; zero, lengths past the receiver, empty receivers, nulls and multiple chunks must preserve Polars behavior.

There is a large-length boundary: `slice_offsets` (`polars-core/src/utils/mod.rs:340-355`) panics when the receiver length exceeds `i64::MAX`. A `ChunkedArray` can in principle reach that length by sharing chunks (record 0093). Before any of these three calls, check `this.0.len() <= i64::MAX` and return a named `ConversionError` if not. This check is about Polars's signed offset contract, not a materialize bound: these methods share buffers rather than copying the whole result. Keep the check before any routed engine call and keep existing callback, slice-copy and iterator budgets unchanged. Do not assume the receiver length is bounded merely because the script's requested length is an `i64`.
