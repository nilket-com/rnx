# rnx 0113: non-serde generic trait impls as one batch

Status: plan. Record 0112 is closed on `origin/main` at `aa2b344`. The target is the pinned Polars v2 Rust API (`da47b7405f0e2d188e71cce7c2d588c695f4098d`); 0.55.2 remains an active compatibility build. The starting v2 scoreboard is 3,651 available and 2,415 value-tested of 6,441 applicable callables. This record decides the **345** rows marked `deferred to 0113, unproved` in `probes/0112/evidence/targets.json.gz` and implements reusable, proved rules. It is one plan and one implementation record, not a record per trait or API.

The frozen rows include `FromIterator` 49, `From` 42, arithmetic operators (`Add`, `Sub`, `Mul`, `Div`, `Rem`) 91, bitwise operators 27, `Clone` 16, `Deref`/`DerefMut` 17, `AsRef`/`AsMut` 12, `Iterator`/`IntoIterator` 21, `Index` 8, `Extend` 5, formatting (`Debug`, `Binary`, `LowerHex`, `Octal`, `UpperHex`) 23, and 34 other rows. These are inventory rows, not expected binding counts; a generic impl can yield several family bindings, and a safe Rust impl can still lack a useful script mapping. Keep the 0112 serde decisions unchanged.

## Shared proof before any family emitter

Build an auditable table keyed by all 345 original inventory keys. For every row record its full trait identity and arguments, receiver, parameters, return, associated types, `owner`, `impl_for`, impl bounds and where predicates, applicable wrapped concrete heads, script mapping, and final disposition. The inventory's `canonical_path` names the trait path while `name` carries arguments such as `From<A>` or `Index<usize>`; use both, and fail closed if the arguments cannot be parsed and reconciled with the method signature. A row on a type's rustdoc page is not proof that the impl is **for** that type: `From<&ChunkedArray<T>> for Vec<Option<T::Physical>>` has an outward `Vec` head, and `AsRef<ChunkedArray<T>> for dyn SeriesTrait` has a foreign head. Do not count these as bindings on `ChunkedArray`.

Synthesize an exact impl head from `impl_for` for the existing applicability solver; foreign trait impl rows currently have no `impl_head`. Unify the whole head, including `&`/`&mut`, lifetime, type arguments, projections and aliases, with the concrete wrapped receiver or target. Discharge every impl bound and where predicate for that pair, including external traits; an empty recorded bound means only what the compiler proves for the exact instantiation. Resolve `Self`, `Self::Output`, `Self::Item`, `Self::Target` and `Self::IntoIter` from **that same impl record** after substitution. Reject missing, extra, ambiguous or non-scriptable associated values. Check `trait_lifetimes`, function generics and method signature separately; no generic parameter may remain unresolved in emitted code.

Validate the whole shape and value mapping **before emitting any binding text or registration**. Treat a wrong trait path, argument count/order, impl head, bound, receiver, parameter, associated type, return, or unsupported feature as a named refusal. Deduplicate aliases by the underlying Rust identity, then apply the existing Rune slot/name collision policy; a second impl must not silently replace the first. Keep the callable status separate from emitted binding count and per-family instantiation pairs. An implementation that cannot be mapped in this record remains a named unsupported row with its contract, not relabelled as available.

## Family rules

Use the established Rune protocols where their semantics fit. Otherwise expose a named method or constructor that says what it does. Each family gets one exact-shape gate and one conversion route, reused across all matching rows; avoid a per-inventory-key release allowlist. The compiler probes below determine the concrete admission set.

1. **Constructors and conversions:** For `From`, `TryFrom`, `FromIterator`, `FromParallelIterator`, `Default` and `Extend`, prove both the input item/source and concrete target. Admit a script vector only when every element has an existing owned mapping, including `Option` validity and narrow integer checks; create the Rust iterator with `Vec::into_iter` after conversion. A parallel trait may use a bounded owned vector's `into_par_iter` only if the relevant feature and compile probe prove that exact impl; otherwise record the Rayon contract. `TryFrom` preserves `PolarsError`; `From` never masks a panic or invokes an unproved target. Outward conversions to a script vector use the 0082/0093 materialization and checked-readback rules; foreign or Arrow elements stay refused unless an existing copier covers them. `Extend` mutates only after all script input is converted and budgeted, and must define behavior if Polars panics or partially mutates. Constructor names must expose the source/item identity and pass collision checks.
2. **Arithmetic, bitwise and unary operators:** Reuse the current Rune operator slots when free; otherwise a clearly named method may be used if it preserves the Rust impl's meaning. Distinguish owned `Self` from `&Self`, and `Self` RHS from scalar, borrowed wrapper or other RHS; never clone an owned operand merely to make a borrowed impl compile. Check the recorded `Output` after substitution, then route fallible scalar conversion before the call. For `N: Num + ToPrimitive` and other numeric generics, instantiate only a proven native pair with a stated narrowing/rounding policy; do not accept a Rune `i64` as every Rust `N` by convenience. Preserve null masks, division/overflow behavior, receiver reuse after conversion error, and the existing engine/panic boundary. Do not add a second competing operator binding for the same Rune slot.
3. **Iteration and views:** `Iterator`, `IntoIterator`, `Deref`, `DerefMut`, `AsRef`, `AsMut` and `Index` can expose owned snapshots or an existing wrapped value, never a borrowed Rust reference or iterator that outlives its receiver. Resolve `Item`, `IntoIter`, `Target` and `Output` exactly. Reuse the 0082 cumulative slice budget and the 0099–0106 chunk snapshot preflight/copy rules for matching items; cap the whole iteration before allocation where a reliable length is available. A streaming iterator with no proven finite bound may be admitted only with a cumulative element/byte budget checked on each yield and a clean refusal when it is exceeded. `Index` must preserve Rust's index/range shape and panic semantics, use checked `usize` input, and copy/wrap the output before returning. Refuse mutable borrowed targets unless an existing in-place mutation protocol proves no alias escapes.
4. **Formatting and value protocols:** `Clone`, `Debug`, `Binary`, `LowerHex`, `Octal`, `UpperHex`, `PartialEq`, `Eq`, `Hash`, `Not`, `Neg` and any remaining value protocol require an exact impl head and signature. `Clone` returns the same wrapped type and must not be used as a universal fallback for consuming impls. Formatting writes into a bounded string builder so a large representation cannot bypass the materialization policy; compare to direct Rust formatting. `PartialEq` or `Hash` does not imply a useful Rune operation if its comparator state, identity, or hash domain cannot be represented. `Drop` and marker-only `Eq` do not earn standalone script operations. `AsyncWrite`, `Write`, `DnsResolver`, `Error`, `ParallelIterator` and similar service traits need an existing Rune abstraction and a proven resource/lifetime contract; otherwise name that contract in the refusal table.

Do not use a generic trait impl as evidence that a method inherited from another trait is callable without checking its own signature. A `Deref` implementation, for example, does not automatically make all target methods available. Do not broaden the denominator or change the 0112 serde JSON boundary to improve the score.

## Compile probes and controls

Before broad emission, compile direct UFCS probes at **both pins** for a passing and failing dtype under one generic `ChunkedArray<T>` head; `FromIterator<Option<T::Native>>` with nulls; an inward and an outward `From`; owned and borrowed arithmetic with a wrapper RHS; scalar `N` arithmetic with boundary values; an operator whose return is `Self::Output`; `Clone` and `Deref` on a concrete owner; and one `Index` or iterator item that borrows storage. Include a negative probe for an unresolved projection or external bound and one for a colliding Rune slot. Record the actual Rust types and results, not just a successful compile exit.

Generator self-tests must mutate one shape field at a time for every emitting family and assert a named refusal with **zero binding text and zero registration**. Include an outward-head row that is not bound on the inventory owner; a borrowed/owned head swap; a wrong trait argument; a wrong associated output; an extra where predicate; an unproved scalar native; an unknown iterator item; and a Rune name collision. Add a real-inventory drift control for a representative generic row, rather than relying only on synthetic structs. Compare generated output to the checked-in release at both pins.

Focused behavior tests compare script calls to direct Rust on representative accepted families: nullable and empty vectors, narrow integer and `u64` read-back boundaries, owned-vs-borrowed receiver reuse, null-preserving binary/scalar operators, division by zero and float specials where relevant, iterator exhaustion and budget refusal, formatting exactness, and no alias escaping from view/index paths. A refusal before a mutating call must leave its receiver usable; if the Rust operation itself can partially mutate before a failure, document that actual contract rather than promising transactionality. Oracle cases should cover each newly available operation with a feasible fixture, including the result's value, validity, error kind or panic as appropriate.

## Evidence, validation and stop rule

Commit a reproducible table of the 345 rows with exact generated/refused/deferred dispositions and named reasons, plus per-pair audits for instantiated generic heads. Reconcile its totals with the generated surface and the prior 0112 table; report available operations, bindings, value-tested operations, full-public and applicable denominators at v2 and 0.55.2. Record every old oracle status movement separately from new cases and explain fixture failures. Preserve pinned inputs, hashes and a clean-checkout replay as in 0112.

Run generator self-tests and drift checks, the full v2 oracle, and the all-features, no-default-features and generated production adapter suites with fail-fast disabled where needed. Measure three interleaved launch sets against the retained 0112 production binary if generated code changes; keep the existing +5 ms launch budget. Rebuild/re-measure if a reviewed amendment changes that binary.

Stop a family when the first probes reveal an unproved owner/bound, unsafe or unbounded borrowed representation, an unavailable native mapping, or a collision that cannot be resolved by one family rule. Finish the other families and keep the stopped rows in the same 0113 audit with their exact reasons. Do not create a new Markdown plan or implementation cycle for each trait or each API touchpoint. If the shared head/bound proof itself cannot be made reliable, stop generation for the whole batch and publish the complete audit before proposing a narrower follow-up.
