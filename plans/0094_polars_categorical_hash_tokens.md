# rnx 0094: lossless categorical hash tokens

Status: plan. Record 0093 closed at plan `ac0f83c` and implementation `0d01a67` on `origin/main`.

## Target and source contract

The 0093 scoreboard is 2,117 script-available operations, 1,344 value-tested and 1,926 unsupported, with 178 refused proven pairs and 656 unresolved family pairs. Record 0093 correctly refuses a `u64` read-back above `i64::MAX`; that makes three categorical hash producers fail for about half their values and prevents a script from spelling the upper half of the hash range for two consumers. This record gives **five existing bindings** a full-width hash representation, without weakening 0093's checked integer rule elsewhere. It is a semantic repair, not a new operation pool.

The exact paths are `Categories::hash` (`polars_dtype:309`), `FrozenCategories::hash` (`polars_dtype:377`), `CategoricalMapping::cat_to_hash` (`polars_dtype:33`), `CategoricalMapping::get_cat_with_hash` (`polars_dtype:27`) and `CategoricalMapping::insert_cat_with_hash` (`polars_dtype:30`). In the pinned Polars 0.55.2 source, the first hashes a Categories identity (`categorical/mod.rs:188-189`), the second returns a FrozenCategories combined hash (`mod.rs:309-310`), and `cat_to_hash` reads a stored `PlFixedStateQuality` hash (`categorical/mapping.rs:85,115-117`). The two `*_with_hash` methods use the mapping's `PlSeedableRandomStateQuality` lookup hash (`mapping.rs:19,54-75`). These are distinct hash domains: **do not promise that a `cat_to_hash` token is valid input to `get_cat_with_hash` or `insert_cat_with_hash`**. They all need the same exact `u64` bits at the script boundary.

Represent a hash as exactly 16 lowercase ASCII hexadecimal digits with no prefix, for example `0000000000000000` and `ffffffffffffffff`. A producer emits that canonical string for all `u64` values. A consumer accepts only that canonical form, parses the whole value, and passes the resulting `u64` to Polars unchanged. A malformed token is a `ConversionError` naming the operation and `hash`, raised before the Polars call. Keep other `u64` returns and parameters on the 0093 checked integer policy; do not add a global string-to-`u64` conversion. This is an exact representation of bits, not a claim that hashes from different Polars domains are interchangeable.

## Gates

1. **Freeze scope and prove reachable values.** Record the five inventory keys, canonical paths, exact return and parameter types, previous signatures, and source citations in `probes/0094/targets.json`. Check the mapping's stored-hash and lookup-hash code and compare their hashers in the pinned source. Compile a probe for each receiver fixture under the adapter build: `Categories::new`, `FrozenCategories::new`, and a mapping from `Categories::mapping` may need their `Arc` unwrapped for the existing concrete generated wrappers. If a fixture cannot be built by a safe public path, document that before changing generation. Use a directly computed `mapping.hasher().hash_one(s)` for positive `*_with_hash` controls; do not reuse `cat_to_hash` as if it were the same domain. Freeze the 0093 binary and its hash before rebuilding.
2. **Implement an exact gate and codec.** Add a release-file policy keyed by both inventory key and canonical path, with the direction (`return`, `hash parameter`) and cited source type; validate the shape before emitting any binding text. Scope it independently for both ordinary and instantiated method emission, and clear it after each callable. Provide a small support codec: `format!("{v:016x}")` for `u64`, strict 16-byte lowercase ASCII hexadecimal input for `u64`, no truncation or signed cast. The three producers return `String`, `String`, and `Option<String>` respectively, subject only to other pre-existing fallibility such as `cat` narrowing. The two consumers take a string hash and retain their existing Polars `Option`/`Result` behavior. Do not parse inside a routed engine closure when pre-call validation is possible. Synthetic generator controls cover all five exact shapes, same-name/unlisted key or path, altered return or parameter type, missing citation, direction mismatch, scope reset, and empty binding text on refusal. The shipped output must contain exactly five hash-token bindings and no change to unrelated `u64` conversions.
3. **Compare bits and behavior.** Add direct Rust-versus-Rune tests for all five methods, using safe fixtures that expose the concrete wrappers under `test-support`. Cover `0`, `i64::MAX`, `i64::MAX + 1`, `u64::MAX` in the codec, plus actual hashes on each producer (including an observed upper-half value or a controlled hash source). Compare each emitted token with `format!("{rust_hash:016x}")`; compare the consumers with direct Polars calls using the mapping's lookup hash. Exercise `None` for an absent category, an existing and a missing lookup, and a successful insertion. Reject short, long, uppercase, prefixed, non-hex and non-ASCII tokens; after each refusal, verify the mapping is still usable. Test a wrong-but-well-formed lookup hash against direct Polars behavior, without equating it to `cat_to_hash`. A producer or consumer is value-tested only after a paired comparison executes, not merely after compilation.
4. **Keep the oracle independent.** For these five exact paths, make the Rust-side oracle format hashes from the original `u64` as canonical hex and make its script side expect strings. Adapt the two consumer argument fixtures so the Rust call receives the same parsed bits as the script call. A negative control must fail if the Rust formatter first casts through `i64` or if the binding truncates the high bit. Add generated oracle cases if the new safe categorical fixtures make that feasible; otherwise report the explicit fixture skip and retain direct paired behavior controls for every target. Regenerate the committed results, explain any pre-existing status movement, and do not count compile-only rows as verified.
5. **Reconcile cost and surface.** Update adapter and generator docs with the token syntax, the five exact methods, and the distinction between stored and lookup hashes. Run generator self-test and drift, both adapter configurations with Cargo fail-fast disabled, and the full all-features oracle. Reconcile operations, bindings, value-tested operations, unsupported reasons and oracle statuses against the 0093 baseline; the expected operation and binding counts are unchanged. Measure three interleaved 60-run cold-launch sets against the retained 0093 binary under the +5 ms budget. Put source and fixture proofs, byte-for-byte token comparisons, oracle tally, binary hashes and raw launch samples in `plans/0094_polars_categorical_hash_tokens_evidence.md`.

The function-generic and Arrow pools remain open. A future general unsigned-integer value type would be a separate design; this record is limited to categorical hash tokens.
