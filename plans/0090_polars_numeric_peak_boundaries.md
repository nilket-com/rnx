# rnx 0090: numeric peak functions with explicit boundaries

Status: plan. Record 0089 closed at plan `eaa540b` and implementation `4344da5` on `origin/main`.

## Target and contract

The 0089 scoreboard is 2,113 script-available operations, 1,340 value-tested, and 1,930 unsupported; 178 proven receiver pairs remain refused. The 0083 census identified `peak_max_with_start_end` (`polars_ops:77`) and `peak_min_with_start_end` (`polars_ops:81`) as unavailable free functions. Each takes `&ChunkedArray<T>, Option<T::Native>, Option<T::Native>` and returns `BooleanChunked`. The first argument fixes `T`; the two scalar arguments are boundaries for the first and last comparison. These are **two free operations**, outside the 178-pair receiver pool.

The proposed scope is the ten existing physical numeric wrapper identities: eight integers (`Int8/16/32/64`, `UInt8/16/32/64`, with `UInt32Type` represented by `IdxCa`) and `Float32/64`. This is a ceiling of **20 bindings and two operations**, conditional on a compile proof and a usable script conversion for each row. Do not infer a generic `T` from a script number. `BooleanChunked` is returned through the existing wrapper.

Pinned Polars 0.55.2 `polars-ops/src/chunked_array/peaks.rs:36-60` shifts the receiver by one in each direction, filling from the supplied optional boundaries, and intersects strict comparisons. `polars-core/src/chunked_array/ops/shift.rs:5-39` makes fresh arrays and leaves the input unchanged; its periods here are constants `1` and `-1`. Audit the comparison implementation reached for all admitted types, including float NaN, nulls, empty arrays, and multiple chunks. No user-controlled sorted flag or unchecked index is part of this path. A failed source or compile audit excludes that type with a cited reason; it does not broaden the gate.

## Binding rule

Extend 0089's exact `(inventory key, canonical path, concrete type)` free-instantiation gate for these two functions. Substitute `ChunkedArray<T>` structurally with its existing wrapper **and** resolve each exact `T::Native` associated-type occurrence to the native scalar of that concrete numeric type. Reject any residual function generic or associated type. A substring replacement must not turn another bound or path into a candidate. Place one static binding per admitted wrapper, borrow its array, and call the public `polars_ops::chunked_array::peaks` function; never clone or consume the receiver.

For integer boundaries, use the existing script integer and checked native narrowing, including `u32` through `IdxCa`; `None` stays `None`. For Float64, use the existing script float. For Float32, follow and document the adapter's existing `f64` to `f32` conversion policy, with explicit tests for finite values, NaN and infinities. The optional conversion must be scoped to the listed functions and type identity, and its fallibility must propagate through engine routing. Do not silently introduce a generic numeric-scalar rule for the other six census entries. No slice copying or callback boundary is involved.

## Gates

1. **Freeze and prove.** Record both keys, canonical signatures and bounds, prior surface reasons, and all 20 proposed `(key, wrapper, T, T::Native)` rows in `probes/0090/targets.json`. Compile direct calls for every proposed type against the pinned adapter build. Inspect `peaks.rs`, `shift.rs`, and the comparison operators reached by the two calls. Classify each row as emitted or excluded with a source and compile citation. Verify the public callee path and use the same concrete type in the direct Rust comparison.
2. **Constrain generation.** Add an exact release-file gate and structural associated-type substitution to the 0089 free-instantiation emitter. Synthetic controls must cover a narrow signed integer, `IdxCa`, Float32, both optional boundaries, `None`, a leftover `T::Native`, an unrelated generic free function, and a path or bound merely containing the target spelling. Confirm the scoped conversion policy clears on every exit and no unlisted callable changes disposition. Compile both adapter configurations and run generator self-test and drift/accounting checks.
3. **Prove behavior.** Compare Rune with direct Rust for every emitted type. Cover empty, singleton, duplicate peaks, nulls, multiple chunks, and explicit start/end boundaries that change the first/last result; include integer overflow/negative-to-unsigned refusals and float NaN/infinity behavior. Assert the input wrapper remains usable with its original length, values and null count. Add paired oracle cases for every emitted binding with a usable fixture; report matches, both-error/panic and unverified cases separately. Do not count a compile-only binding as value-tested.
4. **Reconcile cost.** Run the full all-features oracle and both adapter suites with Cargo fail-fast disabled. Reconcile operations, bindings, value-tested operations, unsupported operations and the unchanged 178-pair pool against the 0089 baseline. Retain and hash the closed 0089 binary before rebuilding; run three interleaved 60-run cold-launch sets under the +5 ms per-record budget, preserving raw samples. Write source citations, per-row decisions, oracle tally, binary hashes and launch results to `plans/0090_polars_numeric_peak_boundaries_evidence.md`; update the adapter and generator READMEs for the actual binding rule.

The other 0083 function-generic candidates, numeric-scalar callables, callback audits, Arrow return pairs, and `with_validities` remain separate. The generator-wide unchecked `usize as i64` audit remains open.
