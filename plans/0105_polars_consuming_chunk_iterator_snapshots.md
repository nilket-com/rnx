The 0104 scoreboard is 2,134 script-available operations, 1,378 value-tested and 1,909 unsupported. Of 98 refused proven pairs, sixteen belong to `ChunkedArray::downcast_into_iter` (`polars_core:3504`, `polars_core::chunked_array::ChunkedArray::downcast_into_iter`). The 564 unresolved generic pairs should not change.

Pinned Polars 0.55.2 `chunked_array/ops/downcast.rs:53-62` takes `mut self`, moves its chunk boxes into a `DoubleEndedIterator<Item = T::Array>`, and casts each owned box under Polars's `T::Array` datatype invariant. `ChunkedArray<T>::clone` in `chunked_array/mod.rs:996-1008` clones its chunk vector and metadata. The adapter's established `self` convention exposes the Rune receiver by reference and consumes a **clone**, leaving the Rune receiver usable. This method must preserve that convention. Call Polars `downcast_into_iter` once on the clone, drive the iterator to completion, and expose only owned `Vec<Vec<Option<script value>>>` in forward chunk order. Preserve empty chunks, nulls and values; copy UTF-8 strings and binary payloads; check `u64` values on read-back as in 0093. No Arrow array or iterator may reach the script.

The clone is proportional to the number of chunks, so **preflight and enforce the materialize bound before cloning or calling Polars**. Preflight the original receiver's borrowed chunks using safe typed downcasts and checked arithmetic, without proportional allocation. One inclusive bound covers one slot per chunk, one per cell including nulls, and one per non-null string or binary payload byte. Then clone, invoke Polars, and stream each owned array directly into the output; do not first collect the owned arrays into another vector. Re-count chunks, cells and bytes against the same preflight total, compare each yielded array length with its corresponding original chunk, and require the final count and slot total to match. A different count or shape, wrong type discovered in preflight, overflow, value conversion failure or budget refusal returns a typed error without a partial result. Budget and overflow messages name the operation, relevant counts and active bound. The original Rune receiver must remain usable after success and every refusal. Keep the 0099–0104 snapshot budgets unchanged.
