# rnx 0089: integer function-generic arg extrema

Status: plan. Record 0088 closed at plan `c66b6de` and implementation `cc6aa61` on `origin/main`. This record takes two free functions from the 0083 function-generic candidate table. Their type parameter is fixed by an already wrapped `ChunkedArray<T>` input, so a script does not need to supply a type annotation.

## Measured target and source contract

The 0088 surface has 2,111 script-available operations, 1,338 value-tested, 1,932 unsupported, and 178 refused proven receiver pairs. `arg_min_numeric` (`polars_core:3153`) and `arg_max_numeric` (`polars_core:3155`) are two unavailable **free operations**, refused because their `&ChunkedArray<T>` parameter has a function-level `T: PolarsNumericType` with the additional `for<'b> &'b [T::Native]: ArgMinMax` bound. They are not members of the 178-pair proven-receiver pool; this record must not subtract its bindings from that pool.

The first concrete policy covers eight integer wrapper identities: `Int8Chunked`, `Int16Chunked`, `Int32Chunked`, `Int64Chunked`, `UInt8Chunked`, `UInt16Chunked`, `IdxCa` (the adapter's `u32` identity), and `UInt64Chunked`. That is a ceiling of **16 new bindings and two newly available operations**. A compile probe against pinned Polars 0.55.2 must prove both trait bounds for each identity before it is counted as emitted. Float32 and Float64 are outside this record. In `polars-core/src/chunked_array/arg_min_max.rs:41-80`, `arg_max_numeric` dispatches a sorted float to `arg_max_float_sorted`; `chunked_array/ops/float_sorted_arg_max.rs:45-71` states an unsafe sorted/non-null precondition. The float path needs its own audit, especially because a script can set the sorted flag. Categorical extrema use a different type family and also remain separate.

The integer functions return `None` for an empty or all-null receiver, otherwise the index of the extremum. They can read contiguous or multiple chunks and consult the sorted flag (`arg_min_max.rs:41-67,163-283`). They do not mutate the receiver. Preserve Polars's tie-breaking, null and sorted-flag behavior exactly; do not substitute the adapter's `arg_min` or `arg_max` method as an implementation shortcut. An incorrectly asserted sorted flag can change the answer in Polars and should be compared as source behavior, while the audit must rule out an unchecked out-of-range access on the admitted integer path.

## Binding rule

Use a release-file gate listing the two inventory keys and eight concrete wrapper/type identities. For a listed free function, substitute the argument's `ChunkedArray<T>` with the matching existing wrapper and infer `T` from its inner type. Emit one binding per compile-proven identity, with the script parameter borrowed for the call; no `ChunkedArray` is cloned or consumed. Keep this rule distinct from the method receiver-family applicability census and from an unrestricted `generic_fn` bucket. A listed function with an unproved type, a return-only generic, or another parameter that cannot be mapped stays refused with its reason.

Map the result to `Option<i64>` using a checked `usize` → script-integer conversion, composing through `Option`: `None` remains `None`, and an unrepresentable index becomes a typed conversion error naming the operation. Reuse `support::widen` from 0087 or an equivalent checked helper. Make the binding fallible if this check can fail. No materialization bound is needed for the scalar result; existing engine routing and panic rules remain in force.

## Gates

1. **Freeze and prove.** Record the two inventory keys, canonical signatures, bounds, current surface dispositions, and all 16 proposed `(key, wrapper, T)` rows in `probes/0089/targets.json`. Compile and run direct calls for each proposed integer type against the adapter's pinned Polars build. Inspect both contiguous and chunked source paths and any `unsafe` they reach, including user-set sorted flags. Mark each row candidate, excluded with a cited reason, or still refused before emission. Report two operations and prospective bindings separately from the unchanged 178 refused proven receiver pairs.
2. **Narrow generation.** Implement the key-and-type-scoped free-function family rule, with an exact release gate and a scope that clears on all exits. Synthetic controls cover one integer alias, `IdxCa`, `Option<usize>` with checked conversion, an unlisted generic free function, an unproved numeric type, a return-only generic, and an unrelated wrapped argument. Compile the emitted adapter with all features and without generated bindings; ensure no unlisted callable changes disposition and no float binding slips in.
3. **Behavior and oracle.** Compare Rune with direct Rust for empty and all-null input, nullable contiguous input, a multi-chunk receiver, duplicate extrema, and ascending/descending sorted flags on integer data. Test the input wrapper remains usable and unchanged. Add a direct `support::widen` over-range control if the existing 0087 unit test does not already cover it; an actual `ChunkedArray` large enough to reach that index is not required. Generate paired Rune/Rust oracle cases for every emitted binding with a usable fixture, and report matches, both-error/panic and unverified cases separately. A compile-only binding is not value-tested.
4. **Evidence and cost.** Run generator self-test, drift/accounting checks, both adapter suites with Cargo fail-fast disabled, and the full oracle. Reconcile the 2,111/1,338/1,932 baseline, emitted operations/bindings, oracle results and the still-separate 178-pair pool. Retain and hash the closed 0088 release binary before rebuilding; measure cold launch in three interleaved 60-run sets under the +5 ms per-record budget, keeping raw samples. Put source citations, compile-probe rows, results, hashes and launch data in `plans/0089_polars_integer_generic_arg_extrema_evidence.md`, and document the type-inference contract in the adapter and generator READMEs.

The remaining 0083 function-generic family candidates, float and categorical extrema, numeric-scalar policy and callback audits await their own decisions. Arrow array returns and `with_validities` remain refused. The broader unchecked `usize as i64` generator audit noted in 0087 remains open outside these two new bindings.
