# rnx 0093: checked integer read-back from Polars

Status: plan. Record 0092 closed at plan `a7b1159` and implementation `db817ca` on `origin/main`.

## Defect and contract

The 0092 scoreboard is 2,117 script-available operations, 1,344 value-tested and 1,926 unsupported; 178 proven receiver pairs are refused and 656 family pairs unresolved. This record fixes the conversion of Polars integers *to* Rune integers; it is not a new API pool. A Rune integer is `i64`. The generated `UInt64Chunked::get` and `first` currently use `u64 as i64`, so values above `i64::MAX` wrap. The 0092 `lhs_sub` test demonstrates a reachable case: Rust returns `18446744069414584324`, while script `.get` reads `-4294967292`. The generated oracle also formats narrow integer types through `as i64`, so it can report a false match for this defect.

For any Polars-to-script scalar with a source type that can exceed the `i64` range, return its exact value if representable and otherwise a `ConversionError` naming the operation and value. Use the existing `support::widen` helper. Apply this to direct returns and nested `Option`, vector, slice and iterator returns, and to values delivered *into* a script callback. Preserve nulls, order, copy bounds, receiver ownership and callback boundary semantics. Do not change script-to-Polars narrowing, Polars arithmetic, or the underlying `UInt64Chunked` values. The first gate determines the precise set of emitted source types and routes; `u64` and `usize` are mandatory, while any emitted `u128`, `i128` or other potentially lossy type must be classified and either checked here or refused with a named reason. `IdxSize` and narrow signed/unsigned primitives may retain a cast only where their full range is provably within `i64` under the pinned build.

## Gates

1. **Census before editing.** From the 0092 inventory, generated bindings and generator source, produce `probes/0093/readback.json` with every Polars-to-script integer conversion grouped by canonical source type, route and callable identity. Distinguish direct returns, nested returns, iterator/slice items, callback inputs, free instantiations, and oracle formatters; do not count `as i64` text alone as a lossy conversion. Identify every reachable `u64`/`usize` route and existing checked exceptions (0087 `chunk_lengths`, 0089/0091 index results). Include a direct value trace for the 0092 `lhs_sub` example and the boundary `i64::MAX`/`i64::MAX + 1`. Audit all other generated `as i64` sites against their source types, including non-generated adapter support and fixture display code, and record which are safely bounded or outside the script read-back path. A synthetic `usize::MAX` control is needed because allocating a collection of that size is not feasible.
2. **Make conversion fallible throughout.** Change `World::ret` to use checked widening for every applicable source scalar, regardless of the old scoped `widen_usize` flag. Ensure its `fallible` bit reaches the emitted Rust signature and error handling through `Option`, `Vec`, tuples, borrowed slices, materialized iterators and receiver methods. Keep the 0082 cumulative materialize guard and 0087 exact iterator length check. In `callback_input`, extend the typed callback-failure conversion path for checked integer arguments, including optional and collection arguments if emitted; perform the check before invoking the script and route failure through the 0080 `CallbackFailure` mechanism. Do not let a `?` escape an infallible Polars callback closure, silently drop an item, or convert an overflow to a panic outside the boundary. A callback refusal must report `CallbackError` at its routed sink and leave the guard/outer allowance restored. Name the operation in every error. Any route that cannot propagate the failure safely must be refused before binding text is emitted and listed in the census.
3. **Make the oracle independently sensitive.** Remove lossy `as i64` formatting for risky source scalars in `oracle_fmt` and the relevant fixture/show helpers. The Rust side should model the adapter's checked read-back: represent an out-of-range value as `ConversionError`, including when nested in an option, vector, slice or iterator, so a paired case compares the actual result rather than two wrapped integers. Keep the full Rust value available in evidence for the `lhs_sub` example. Add a negative oracle control that would fail if the generated binding still wrapped, and a control that would fail if the Rust formatter wrapped. Regenerate results and explain any status movement in pre-existing cases; do not count an error/error agreement as a value match.
4. **Prove behavior and reconcile.** Add direct tests at `i64::MAX`, `i64::MAX + 1` and `u64::MAX` using Rust-backed UInt64 fixtures. Cover `get`, `first`, an optional null, a copied slice, an iterator path if emitted, and at least one `u64` callback input (including a routed sink and post-failure reuse). Exercise `usize` on the helper and a synthetic generated return; test a bounded real count. Compare direct Rust values and validity with the script result. Verify that formerly infallible methods now yield `Result` only when required, and update affected scripts and docs. Generator self-test must cover fallible shape propagation, callback conversion, operation names and no residual unchecked risky cast in emitted read-back. Run both adapter suites with Cargo fail-fast disabled, the full all-features oracle, drift and accounting checks. Reconcile operations, bindings, value-tested operations, unsupported reasons and oracle outcomes against 0092; semantic changes need not change operation counts. Retain and hash the closed 0092 binary before rebuilding, then measure three interleaved 60-run cold-launch sets against it under the +5 ms budget. Put the census, source citations, direct value evidence, oracle tally, hashes and launch samples in `plans/0093_polars_checked_integer_readback_evidence.md`.

The remaining function-generic and Arrow pools stay open. This record must leave no emitted Polars-to-script integer conversion whose source range exceeds `i64` using unchecked `as i64`.

## Amendment (agreed with Codex during implementation)

Option B: a release-file allowlist `[[bounded_readbacks]]`, keyed by inventory identity with a source citation, keeps a plain integer return for a `usize` result that is proven to be the length of, or an index into, a `Vec` or `IndexMap` (at most `isize::MAX`), converted exactly with a compile-time `usize` width assertion and a debug assertion. A name alone is insufficient; estimates, configuration sizes, hashes and unproven paths stay checked. `ChunkedArray` lengths are excluded: `append` only `checked_add`s the length (no `IdxSize` limit), and appended chunks share buffers, so a self-append can exceed `i64::MAX` without violating any Polars check. `len`, `null_count`, `height`, `shape`, array indices and other unproven counts therefore use checked widening and become `Result`. Negative controls cover an unlisted same-named callable and an out-of-range unbounded return.
